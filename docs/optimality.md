# Общая мера «оптимальности условий» и протокол против «сада расходящихся тропок»

Запрос владельца 25.10: (1) риск, что мы бесконечно перестраиваем среду, пока эффект не появится, и
результат окажется специфичным для выбранной модели; (2) у каждого этапа свой критерий успеха, но общей
меры «оптимальных условий» нет. Документ закрывает обе части: сначала мера (раздел 1), затем протокол
воспроизведения и инвариантности к метрикам (раздел 2), затем учёт числа переделок (раздел 3).

---

## 1. Общая мера: набор условий, а не одна цифра

Единая скалярная «оптимальность» здесь невозможна: устойчивость, наследуемость, возможность отбора и
цена признака — разные величины, и любая свёртка была бы произвольной. Поэтому мера задаётся как
**вектор из пяти компонент**, каждая считается **одинаково** в любом мире и на любом условии:

| компонента | величина | как считается (одинаково для всех миров) |
|---|---|---|
| **P** — устойчивость | доля прогонов, доживших до горизонта | `alive_final > 0` при фиксированном горизонте; доля с интервалом Уилсона |
| **H** — наследование | сколько поколений переживает наследие | полураспад поднятого ресурса / смена поколения (уже есть: 1.3–2.4) |
| **S** — возможность отбора | `I_obs / I_null(95 %)` | тот же критерий, что в §4i; медиана по сидам |
| **R** — отклик | устойчивость знака `ρ(признак, w)` | доля сидов с тем же знаком и медиана ρ |
| **C** — цена | `ρ(признак, клетко-шаги \| энергия)` | медиана и знак по сидам |

**Условие считается выполненным**, если его компонента пересекла **предзарегистрированный порог**
(для S — `I_ratio > 1` и ≥7/10 сидов; для R — медиана ρ ≥ 0.3 и ≥7/10; для C — медиана ≤ −0.3 при
контроле; для H — полураспад ≥ 1 поколения; для P — выживание ≥ 0.5 с интервалом).

**Оптимальность условий** = число выполненных компонент из пяти (0–5). При равенстве — сравнение по
`S` (возможность отбора), затем по разбросу между сидами (меньше — лучше). Это даёт:
- сравнимость миров (W1, W2-bud, W1-niche) и параметров внутри мира;
- отсутствие «подгонки»: пороги зафиксированы до прогонов, а число выполненных компонент — счётчик, а не
  подбираемая величина;
- возможность честно сказать «условие X не выполнено», а не «не хватило времени».

Текущее состояние по этой мере (25.10, из артефактов):

| мир | P | H | S | R | C | выполнено |
|---|---|---|---|---|---|---|
| W1 (колониальное почкование) | да | да (1.3–2.4) | **нет** (`I = 0`, 0/10) | нет | нет (нет линий) | **2 из 5** |
| W2-bud (клеточное почкование) | да | да | **да** (8.22×, 10/10) | **не вынесен** (невалидно по данным) | **направление есть**, вердикт не вынесен | **3 из 5** |

## 2. Протокол против «сада расходящихся тропок»

Риск сформулирован верно: серия переделок мира, каждая документирована, но вместе они повышают шанс,
что эффект специфичен для нашей конфигурации. Три обязательных шага для **любого** заявляемого эффекта
(начиная с W2-bud):

### 2.1 Воспроизведение на новых начальных условиях
Тот же мир, но **новые сиды**, которых не было при разработке (для W2-bud использованы 1–10 ⇒
брать 101–110), и **новые начальные состояния** (другая раскладка ресурса / другой размер колонии).
Критерий: `S` и `C` воспроизводятся по тем же порогам. Эффект, который держится только на сидах
разработки, помечается «специфичен для выборки».

### 2.2 Устойчивость к разумным изменениям параметров
Предзарегистрированная сетка **до** запуска: `mutation_rate` (±×2), длительность (600 → 900), `eps`
(4 → 6), размер сетки (32 → 48). Критерий: знак и порядок величины `S` и `C` сохраняются в ≥ 3/4
конфигураций. Конфигурации, где тест стал нечувствителен (по арифметике §3c), **не считаются
опровержением** — они считаются «тест не дотянулся» и указываются явно.

### 2.3 Инвариантность к устройству метрики
Каждый заявляемый эффект пересчитывается **тремя** вариантами метрики:
- `w` = споры / живые клетки (основная) → и `w` = споры (сырое число) → и `w` = ⌊споры / клетки⌋ с
  порогом (дискретизация);
- линии: порог «≥5 клеток» → «≥3 клетки» → «все линии со спорами»;
- нуль-модель: `rate = sum/sum` → `rate = mean`.
Эффект заявляется, только если **все варианты дают один знак**. Если знак зависит от метрики — это
публикуется как «эффект зависит от определения», а не выбирается удобный вариант (правило §3c про
нормировку).

### 2.4 Что не считается воспроизведением
Повтор на тех же сидах с изменённым логгером; повтор с изменённым правилом мира (это новый мир);
«воспроизведение» на пилоте из 2 прогонов.

## 3. Учёт переделок: сколько конфигураций мы прошли до эффекта

Чтобы риск «сада тропок» был виден читателю, у каждого заявляемого эффекта указывается **счётчик
переделок**: сколько постановок не дало результата до появления эффекта. Это не наказание, а
прозрачность.

| эффект | переделок до результата | что менялось |
|---|---|---|
| отбор возможен (S) | **4** | колониальное почкование → клеточное; `mutation_rate` 0.01 → 0.05; `eps` 0.1 → 2.0 → 4.0; гейт манипуляции 3 кандидата |
| цена признака (C) | **3** | нормировка энергии (клетко-шаги → время); логгер энергии; 20 → 10 сидов |
| наследование среды (H) | **3** | kill-and-keep v1, v2, v3 — все нечувствительны по конструкции |
| «инвазия не удаётся» | **4** | V8 → merge=keep → режим гибели → фазовая развёртка (и перечитывание механизма) |

**Правило:** эффект с счётчиком переделок ≥ 3 требует **обязательного** прохода по 2.1–2.3, иначе он
не заявляется. W2-bud сейчас имеет 4 переделки ⇒ воспроизведение на новых сидах и параметрах
**обязательно**, а не «желательно».

## 4. Что это меняет в очереди

Новые пункты (пре-регистрация до данных, impact по важности):

1. **`W2bud_replication`** (impact 5, ~1.5 ч): сиды 101–110 + новая раскладка ресурса; критерий — S и C по тем же порогам.
2. **`W2bud_param_sweep`** (impact 4, ~2.5 ч): 4 конфигурации × 10 сидов, сетка зафиксирована до запуска.
3. **`W2bud_metric_variants`** (impact 4, ~0 ч GPU, только пересчёт): три варианта `w`, три порога линий, две нуль-модели.
4. **`conditions_measure`** (impact 3, CPU): считать P/H/S/R/C по всем мирам и держать таблицу в `docs/optimality.md`.
5. **`W1-niche`** (impact 4): механизм возврата энергии при смерти — отдельный мир, отдельная пре-регистрация.

Порядок: `W2bud_metric_variants` (бесплатно, сразу) → `W2bud_replication` → `W2bud_param_sweep` →
`W1-niche`. Пока идёт V1c (геометрия подсадки), GPU свободен, и `W2bud_replication` можно запускать
сразу после него.
