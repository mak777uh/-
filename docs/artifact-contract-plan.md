под машиночитаемые артефакты (запрос пришёл от лида по деньгам, см.

`_hourly/grants/plan-v1.1.0-boss-reply.md`). Этот документ — то, что я реально

## 1. Идея в одном абзаце

Каждый прогон оставляет **научную карточку** — маленький JSON с классом,
метриками и признаком пре-регистрации, — а из манифестов раннера и карточек
собирается **индекс прогонов**, который и отдаётся наружу (Zenodo, заявки,
рецензент). Числа внутри карточки берутся только из артефактов; где данных нет —
`null` и `unknown`, а не оценка. Манифесты и журнал при этом не трогаются: они
остаются историей, как требует §2.

## 2. Структура репозитория: что добавляется и что меняется

| Путь | Статус | Что это | Можно ли править руками |
|---|---|---|---|
| `lab/runs/<run_id>.json` | **есть** | манифест раннера: команда, коммит, окружение, статус | **нет** (§2, §7) |
| `lab/science/<run_id>.json` | **новое** | научная карточка: класс, метрики, пре-регистрация, ссылки на артефакты | да, это новый файл |
| `lab/runs.index.json` | **новое** | плоская таблица «манифест + карточка» для внешнего мира | **нет**, генерируется |
| `lab/schema/run.schema.json` | **новое** | схема карточки | да, при расширении enum |
| `lab/schema/runs_index.schema.json` | **новое** | схема индекса | да |
| `scripts/validate_runs.py` | **новое** | валидатор (acceptance test) | да |
| `scripts/convert_runs.py` | **новое** | конвертер истории в карточки | да |
| `scripts/build_runs_index.py` | **новое** | сборка индекса (+ CSV для заявок) | да |
| `docs/protocol.md` | **новое** | протокол проверки численного режима | да, подписывается учёным |
| `repro/Dockerfile`, `repro/README.md`, `make repro` | **новое** | smoke-воспроизведение 200 шагов, tf32/fp32 | да; **CI этот шаг не запускает** (нет GPU) |
| `lab/registry.json`, `lab/checkpoints.json`, `lab/state.json`, `lab/queue.json` | **есть** | без изменений по смыслу; в registry — ссылка на карточки | генерируется/ведётся как раньше |
| `README.md`, `reports/`, `articles/`, `manuscript/` | **есть** | без перестройки; в README — одна строка про артефакты | по правилам §6a |

Ничего не удаляется и не переписывается: перестройка аддитивная. Если карточка
есть, а манифеста нет — это ошибка CI; если манифест есть, а карточки нет — это
«прогон без научного следствия» (для тренировок без переписи допустимо, для
переписей — нет, см. правила ниже).

## 3. Правки контракта AGENTS.md

### 3.1 §2 «Что считается истиной» — добавить иерархию слоёв

Вставить после списка приоритетов: манифест (слой A) — факт о запуске; научная
карточка (слой B) — интерпретация чисел из артефактов; индекс (слой C) —
представление для внешнего мира. Карточка не может противоречить артефактам:
CI сверяет класс с `summary_*.json`, а `best_loss` — с журналом/манифестом.
Приоритет при расхождении: артефакт → карточка → индекс.

### 3.2 §6 «Обязательный след эксперимента» — расширить пункт 3

К существующим 10 пунктам добавить:

- **3a.** `lab/science/<run_id>.json` для каждого прогона, у которого была
  перепись (класс, метрики, ссылка на `census`/`summary`, `preregistered`);
- **3b.** `lab/runs.index.json` пересобран (`make index` / скрипт), diff в CI
  зелёный;
- **3c.** для прогонов, где класс ещё не посчитан (тренировка без переписи),
  карточка не требуется, но в манифесте должен быть `status != running`.

### 3.3 Новый §6b «Контракт артефакта v1.1» — правила заполнения

1. **Источник чисел** — только артефакты в git: `summary_*.json`,
   `journal.jsonl`, `lab/checkpoints.json`, манифест. Никаких «по памяти».
2. **`regime`** — точность, не железо: `tf32` \| `fp32` \| `fp32_no_tf32_hw`
   (карта без TF32: T4, V100) \| `cpu` \| `unknown`. Железо и версии — в
   `env`/манифесте.
3. **`class`** — доминирующий класс переписи: `struct_1`, `struct_2`,
   `uniform_dark`, `uniform_bright`, `death`, `mixed` (порог не взят ни одним),
   `n/a` (переписи не было), `unknown`.
4. **`preregistered`** — `true` только если в репозитории есть план с критерием,
   закоммиченный **до** старта; иначе `unknown`. Задним числом `true` не ставится.
5. **`weights_sha256`** — если веса существует, хеш обязателен и сверяется с
   `lab/checkpoints.json` или с файлом.
6. **Кто заполняет.** Научные поля — учёный (исполнитель или ведущий), не
   оператор и не агент по деньгам. `source: converted` — только скрипт.
7. **Запрещено** переписывать карточку так, чтобы менялся класс или метрики
   закрытого результата: уточнение — новой карточкой/новым прогоном, а не правкой.

### 3.4 §7 «Запрещено» — добавить

- публиковать наружу (Zenodo, Giveth/Gitcoin, arXiv, депозит) без «ок» владельца;
- править карточку закрытого прогона задним числом;
- класть в карточку числа, которых нет в артефактах (в том числе «примерно»);
- гонять `make repro` в CI и выдавать это за воспроизведение на GPU.

### 3.5 §8 «Git» — теги

- `v1.x.y` ставится только при зелёном CI и после локального `make repro`
  (лог прикладывается к отчёту);
- тег не двигается задним числом; новая версия — новый тег;
- `_zenodo/`, `_hourly/grants/` — не зона репозитория: не коммитятся.

### 3.6 Роли (новый короткий раздел §4a)

- **Оператор/бос** (я): схема, CI, конвертер, индекс, теги, релизы внутри репо.
- **Учёный** (исполнитель + я на своих прогонах): класс, метрики,
  `preregistered`, `docs/protocol.md`, матрица экспериментов.
- **Деньги** (агент по грантам): только внешняя упаковка и заявки; в репозиторий
  не пишет; просит изменения через доску.

## 4. Что проверяет CI (гейты)

1. `scripts/validate_runs.py` — схема карточек и индекса, падает на битом JSON,
   неверном enum, `run_id` ≠ имени файла, отсутствии манифеста.
2. `scripts/build_runs_index.py --check` — пересобирает индекс и падает, если он
   разошёлся с файлами (тот же приём, что с `seed_grid.json`).
3. Сверка карточки с артефактом: `class` против `summary_*.json`, `best_loss`
   против журнала, `weights_sha256` против `checkpoints.json`.
4. Всё, что уже есть: `lab.py validate --ci`, пересчёт чисел E02c, пересборка
   сетки, проверки текста, тесты, квитанция воспроизведения.

## 5. Порядок миграции (что и когда делаю)

**Этап 0 — готово (сегодня).** Схемы, валидатор, каталог `lab/science/` с
README, CI-шаг, 6 тестов. Коммит `1cfaa1c`.

**Этап 1 — сегодня ночью (CPU, GPU не занят).**
`lab.py run` получает `--regime` и `--weights-sha256 auto`; поля пишутся только в
**новые** манифесты; тесты на оба флага. Старые манифесты не трогаются.

**Этап 2 — завтра утром.**
`convert_runs.py`: 95 манифестов → карточки, где есть данные (класс из сводок,
метрики из журнала), `unknown`/`null` где нет; `build_runs_index.py` + CI-гейт на
дрейф; CSV рядом для заявок. Ожидаю: карточек на все переписи (~20), у остальных
только тренировочные метрики.

**Этап 3 — завтра днём.**
`docs/protocol.md` (чек-лист численного режима), `repro/Dockerfile`,
`make repro`, `make index`, `repro/README.md` с честной оговоркой про GPU;
локальный прогон 200 шагов в двух режимах; тег `v1.1.0`.

**Этап 4 — это уже v1.2, не в этот релиз.** Матрица: сначала 4 сида ×
{tf32, fp32} × 2000 шагов (8 прогонов, ~5 ч GPU), затем горизонт 4000; baselines
`untrained` (уже есть в каждой переписи) и `random-init` (нужно формально
определить в протоколе).

## 6. Что меняется в текущей работе прямо сейчас

- Закрытие прогона теперь включает карточку: я и исполнитель заполняем её сразу,
  иначе `lab.py validate`/CI будет красным.
- В отчётах и статьях числа разрешено цитировать только с указанием `run_id`,
  чтобы читатель мог открыть карточку.
- Ночная программа (H-REPRO-5/6) идёт как идёт; её прогоны получат карточки на
  этапе 2 — по факту, без переписывания манифестов.

## 7. Риски и как снимаю

| Риск | Снятие |
|---|---|
| Схема окажется тесной (новый класс/режим) | enum расширяемый, `class_extra` для нестандартного; правка схемы — отдельным коммитом |
| Конвертер создаст «красивые» числа | только из артефактов, `null`+`notes`, `preregistered: unknown` |
| Индекс станет шумным | в записи есть `status`; наружу можно фильтровать `finished` |
| CI замедлится | валидация ~100 JSON < 1 с |
| Двойная бухгалтерия (registry/checkpoints/index) | индекс — производное; истина в манифестах и артефактах |
