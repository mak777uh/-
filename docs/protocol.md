# Страница 1. Карточка «делай так»

## Три координаты любого утверждения о классе

1. **Режим** — точность обучения: `tf32` / `fp32` / `fp32_no_tf32_hw` / `cpu`.
2. **Горизонт обучения** — сколько шагов обучали и какой чекпоинт взяли.
3. **Длина роллаута** — сколько шагов CA прогоняет перепись.

Формулировка: «на горизонте 2000 шагов в режиме TF32 при роллауте 2000 шагов
модель даёт `struct_2` 64/64». Без любой координаты утверждение не принимается.

## Пять обязательных контролей в каждой переписи

1. 64 детерминированных старта из фиксированного пула;
2. замороженные центроиды E02b для имени класса;
3. устойчивость последней четверти (замороженная) **и** fit-относительная;
4. положительный контроль (канонический чекпоинт) и `untrained_current_arch`;
5. сырые строки на каждый старт + сводка.

## Что писать в каждом отчёте о классе

- три координаты (п. 1);
- распределение по стартам (`frozen_class_counts`), а не только доминанту;
- разброс дескрипторов между стартами (std `binary_fraction`, `alive_fraction`);
- шкала тривиальности (см. §7): тривиален ли класс;
- если утверждение о частоте — как выбирались сиды (см. §4).

## Красные флаги (утверждение не принимается)

- нет режима, горизонта или длины роллаута;
- класс без контроля в той же переписи;
- «частота» по неслучайной выборке сидов;
- частота, смешанная из разных стеков;
- лизия, оценённая только меткой класса;
- IoU без проверки провенанса прототипа;
- сравнение fit-устойчивости между переписями.

# Страница 2. Почему так, и остальные правила

## 1. Почему три координаты обязательны

Траекторный зонд по одному прогону (сид 42, чекпоинты 1000/2000/3000/4000):

| Шагов | TF32 | FP32 |
|---|---|---|
| 1000 | `uniform_dark` | `uniform_dark` |
| 2000 | **`struct_2` 64/64** | `struct_1` 64/64 |
| 3000 | `struct_1` | `struct_1` |
| 4000 | `death` | `struct_1` |

Класс — фаза траектории, а не свойство модели. Точность меняет маршрут: первые
фазы совпадают, дальше пути расходятся.

## 2. Перепись: что можно и чего нельзя

Можно: называть класс, если он взят ≥ 52/64 и устойчивость последней четверти
(замороженная) ≥ 0.80. Нельзя: называть классом случай, где порог не взят ни
кем — это `mixed`; сравнивать fit-устойчивость между переписями.

## 3. Кривая «класс от длины роллаута»

Для каждого заявленного класса — 500 / 1000 / 2000 / 3000 шагов роллаута
(`scripts/census_curve.py`). Утверждение «модель держит класс» допустимо, только
если класс одинаков на всех длинах или явно указана граница.

## 4. Частоты: только случайная выборка сидов

Утверждение вида «`struct_2` встречается в X% сидов» требует **случайного draw**
из пространства сидов с указанием процедуры (сид-генератор, диапазон, дата
фиксации) **до** прогона. `seed42` — базовый сид, а не случайный: «1 из 8» — не
вероятность. Минимум для частоты — 10 сидов, для доверительного интервала — 20–30
(бутстреп по сидам, а не по стартам: старты внутри модели не независимы, R7).

**Стеки не смешиваются.** Частота, посчитанная по сидам из TF32 и FP32 вместе, —
ошибка: получится смесь двух режимов, а не рецепт.

## 5. Базлайны: три, а не один

| Базлайн | Что это | Обязателен |
|---|---|---|
| `untrained_current_arch` | архитектура без обучения | всегда |
| `random_init` (shuffle) | те же веса, значения перемешаны внутри тензоров (распределение сохранено) | всегда |
| `random_init` (rms) | те же веса, гаусс с тем же средним и СКО | для способностей |

`morphogenesis/make_random_init.py`. **Ветки предрегистрируются:** если из
random-init появляется `struct_1` — это подтверждает, что класс архитектурный;
если появляется `struct_2` — это крупный результат (структура без обучения) и
одновременно проблема интерпретации, и обе ветки фиксируются до прогона.

## 6. Descriptor-level readout обязателен

Класс без дескрипторов — слишком груб: половина, восстановленная до 13% **IoU**
с прототипом, всё равно получает метку `struct_2`. Поэтому в отчёт идут:

- класс + распределение по стартам;
- IoU с прототипом (только после §6a);
- распределение IoU по стартам, а не среднее;
- лево-правая дисперсия — **знак**, не величина (величина при фиксированной
  геометрии — шум, псевдорепликация).

### 6a. Провенанс прототипа до любого IoU

Перед любой абляцией: проверить, что `none`-контроль воспроизводит фигуру
прототипа (в истории был инвертированный флаг `is_trained`, из-за которого
контроль и прототип менялись местами). IoU без этой проверки не считается.

## 7. Шкала тривиальности класса

Класс считается **нетривиальным**, если одновременно:

1. **удалён от вырожденных центроидов:** расстояние в z-пространстве до
   ближайшего из `death` / `uniform_dark` / `uniform_bright` выше порога;
2. **воспроизводим:** разброс дескрипторов между 64 стартами ниже порога (форма,
   а не лотерея);
3. **не «случаен по топологии»:** число компонент/дырок далеко от того, что даёт
   перемешанный контроль.

Пороги **фиксируются заранее** на 12 канонических моделях и попадают в
`lab/schema/triviality.json` до применения к кандидатам. Без этой шкалы
«инвариантный класс» двусмысленно: инвариантны ровно вырожденные.

## 8. Восстановление: класс-независимо

После повреждения (ампутация q, срез, обнуление каналов) меряем:

1. вернулся ли **любой** устойчивый порядок (не `death`, не `mixed`, устойчивость
   выше порога);
2. время оседания (`settle_step`);
3. IoU с неповреждённым финалом (после §6a);
4. доля живых и её восстановление.

Класс — справочная метка, а не критерий.

## 9. Способности: батарея (предрегистрация веток)

| Способность | Метрика | «Есть» | Ветки |
|---|---|---|---|
| Удержание границы | `alive_fraction` + резкость границы | выше untrained на ≥ 0.2 и ≥ 2σ | есть / нет / как у random-init |
| Восстановление | §8, q=0.2 | возврат ≥ 90% стартов, оседание < 1000 шагов | есть / нет / только до порога |
| Регуляция | после возмущения 10% площади возврат к дескриптору в пределах 10% | ≥ 80% стартов | есть / нет / дрейф к другому классу |
| Габитуация | **стресс-канал (ch15)** как стимул: повторяющийся стресс, ответ меряется по `alive`/дескриптору | падение амплитуды ≥ 30% между 1-м и 5-м | есть / нет / сенситизация |
| Вырожденность | разные наборы каналов → та же функция | ≥ 2 непересекающихся набора | есть / нет |

Тезис: **классы между режимами не переносятся, способности — могут.** Способность
считается субстрат-инвариантной, если держится в TF32 и FP32 и одновременно выше
обоих базлайнов.

## 10. Две цели: три ветки, не одна

При детерминированных роллаутах «два бассейна» — это:

1. **разделение:** 64 старта детерминированно делятся на два класса с устойчивым
   членством;
2. **переключение:** старты распределяются по классам, но членство неустойчиво по
   времени (фаза внутри роллаута);
3. **смесь:** один класс, промежуточный по дескрипторам (не два бассейна).

Все три ветки предрегистрируются до прогона, с отдельными критериями.

## 11. Артефакты и депозит

1. В git — манифесты, журнал, сводки, карточки, индекс.
2. В депозит (Zenodo) — **сырые** `census_*.json`, `summary_*.json`, CSV индекса,

## 12. Любая гипотеза пишется с полем «что опровергнет»

До прогона, в плане: формулировка, артефакт-свидетель, критерий, **что именно
опровергнет**, и ожидаемые ветки исходов. Гипотеза без поля «опровергнет» не
запускается.

## 13. Чек-лист для чужой работы (то, что мы хотим видеть у других)

1. Режим: GPU, фреймворк, версии, точность (TF32/BF16/FP32).
2. Горизонт обучения и почему именно он; какой чекпоинт оценивается.
3. Длина роллаута при оценке.
4. Сиды: сколько, случайны ли, сообщён ли разброс.
5. Базлайны: необученная архитектура и случайная инициализация в масштабе.
6. Устойчивость внутри переписи, а не только средний IoU.
7. Опубликованы ли чекпоинты и сырые прогоны.
