## 1\. МИССИЯ И КОНТЕНТ

### 1.1. Что мы строим

Мы создаём экспериментальный стенд для проверки идей биологического морфогенеза и коллективной регуляции на базе Neural Cellular Automaton.

Ключевые принципы:

- самоорганизация из шума;  
- восстановление после повреждений;  
- устойчивость к целевой форме;  
- локальные правила без глобального контроллера;  
- стремление к целевой топологии;  
- обмен стрессом как координационный сигнал;  
- старение как потеря устойчивости аттрактора;  
- минимальные вмешательства вместо внешнего микроменеджмента;  
- стигмергическая память агента.

Рамка «свободный самообучающийся интеллект» является концептуальной мотивацией, а не строгим научным утверждением.

### 1.3. Ключевые идеи для текущей версии

| Идея | Смысл |
| :---- | :---- |
| Локальность | Каждая клетка видит только ближайших соседей. Нет глобального управляющего центра. |
| Топология важнее геометрии | Существенны инварианты: β₀, β₁, χ \= β₀ − β₁. |
| Фазовые переходы и критичность | Малые изменения локальных правил могут резко менять глобальное поведение. |
| Канализация по Уоддингтону | Устойчивая система приходит к целевой форме из разных состояний и после повреждений. |
| Иерархия и дальние связи | В текущей версии не включены, только дорожная карта. |
| Стресс-шеринг | Девиационное/пластическое поле может распространяться по ткани как сигнальное поле. |
| Старение как потеря устойчивости | Деградация аттрактора измеряется ростом энтропии, дрейфом топологии и потерей устойчивости. |
| Минимальные вмешательства | Агент ищет самоподдерживающиеся режимы, а не постоянно «рулит» системой. |

### 1.4. Что конкретно выращиваем

Мы выращиваем Neural Cellular Automaton — дифференцируемую сетку клеток.

Каждая клетка:

- видит соседей в радиусе 1;  
- принимает решение только по локальной информации;  
- обновляет состояние малым шагом;  
- может быть живой или мёртвой по альфа-каналу;  
- может читать стресс-канал как системный сигнал.

Цель обучения:

- из случайного шума получить заданную топологическую мишень;  
- восстановить мишень после повреждения;  
- адаптироваться к изменению цели;  
- удерживать целевой режим без постоянного внешнего принуждения;  
- демонстрировать минимальную деградацию или восстанавливаться после неё.

### 1.5. Честное позиционирование научного вклада

Главный научный вклад v5.5 — не топология как дифференцируемый лосс и не «свободный интеллект», а:

- стресс-шеринг как прокси координационного сигнала;  
- экономика минимальных вмешательств как агентская политика.

Если измеримо будет показано ускорение регенерации или снижение числа вмешательств при сохранении морфостаза — это уже публикабельный результат относительно обычных Growing NCA.

Топологические инварианты в текущей версии — наблюдаемые, не цели. Гипотеза проверяется через корреляцию MSE, Chamfer-метрики и β₀, а не через topological loss.

⚠️ Для публикаций: держаться формулировок данного раздела. Рамка «свободный интеллект» — концептуальная мотивация, а не научное утверждение.

⚠️ Риск тривиализации: стресс-канал — это hand-crafted поле с фиксированной динамикой; сеть его только читает. Если абляция покажет нулевую разницу — это валидный результат. Если стресс помогает, но пространственно перемешанный стресс помогает так же, это означает, что важна не пространственная информация, а наличие дополнительного контекстного канала.

⚠️ **Известное ограничение (gameable signal):** стресс-вход считается из |delta| самой модели. Теоретически сеть может научиться маскировать или генерировать девиации, чтобы манипулировать стресс-сигналом. Контроль STRESS\_SHUFFLE\_MODE частично ловит это, но полностью не исключает. Данное ограничение должно быть зафиксировано в отчётах и memory/discoveries.md.

### 1.6. Честная оценка влияния стресса на динамику

При DT \= 0.1 и STRESS\_TEMP\_SCALE \= 0.10 максимальное увеличение шага составляет \+10% (с 0.1 до 0.11). При DT ≥ 0.45 эффект полностью поглощается клампом DT\_MAX\_EFFECTIVE \= 0.5.

**Вывод:** реальное влияние стресса на темпоральную динамику минимально. Основная ценность стресс-канала — **информационная** (входной контекстный признак для CellBrain), а не темпоральная. В гипотезах и отчётах не следует рассчитывать на «пластичность через DT» как на основной механизм эффекта.

## 2\. ЧЕСТНАЯ ПОЗИЦИЯ ПО ТОПОЛОГИЧЕСКОМУ ЛОССУ

### 2.1. Топология недифференцируема

β₀ и β₁ — целочисленные величины. Их нельзя напрямую использовать в loss.backward().

### 2.2. Рабочая позиция

- Обучение идёт по пиксельному MSE.  
- Топология используется только как метрика мониторинга и для агентских решений.  
- β₀, β₁, χ, плотность, энтропия, стресс, доменные стенки и симметричный Chamfer логируются с заданной частотой.  
- В будущем допустимы дифференцируемые аппроксимации, но в текущей версии они не используются.

### 2.3. Почему это допустимо

Для простых целевых масок минимизация MSE может приводить к нужной топологии как побочному эффекту.

Пример:

- цель — три круга;  
- MSE заставляет систему повторять форму;  
- при успешном обучении β₀ становится близким к 3\.

Но гарантия топологического соответствия отсутствует. Это нужно явно учитывать в отчётах.

### 2.4. Явная оговорка для экспериментов

Во всех фазах, где используется геометрический MSE, обязательно писать:

> «Соответствие β₀ является побочным эффектом геометрической цели. Истинный топологический лосс отложен до будущей версии».

### 2.5. Целевая топология как вектор

Каждая цель должна иметь явный целевой топологический вектор:

TARGET\_TOPOLOGY \= {

    "b0": int,

    "b1": int,

    "chi": int

}

Для трёх кругов:

TARGET\_TOPOLOGY \= {"b0": 3, "b1": 0, "chi": 3}

Для кольца:

TARGET\_TOPOLOGY \= {"b0": 1, "b1": 1, "chi": 0}

### 2.6. Топологическая галлюцинация

Вводится флаг:

topological\_hallucination \= (

    mse \< MSE\_HALLUCINATION\_THRESHOLD

    and (

        abs(b0 \- target\_b0) \> TOPOLOGY\_TOLERANCE\_B0

        or abs(b1 \- target\_b1) \> TOPOLOGY\_TOLERANCE\_B1

    )

)

Смысл: геометрически система может выглядеть похоже на цель, но топологически быть неверной.

Такие случаи обязательно:

- логируются;  
- попадают в отчёт;  
- записываются в memory/discoveries.md.

⚠️ Ограничение флага: topological\_hallucination ловит расхождение β₀/β₁, но не ловит «полумесяцы», «гантели» и лишнюю массу, когда β₀ совпадает, но геометрия неверна. Для этого агент обязан читать symmetric\_chamfer\_error.

### 2.7. Гистерезис флага топологической галлюцинации

Во время регенерации MSE может уже упасть ниже порога, пока β₀ не догнал целевое значение. Флаг может вспыхивать на переходных состояниях.

Правило: флаг считается установленным только при удержании условия в течение HALLUCINATION\_PERSISTENCE отчётов подряд.

HALLUCINATION\_PERSISTENCE \= 3

Реализация:

- вести счётчик hallucination\_streak;  
- если условие истинно — hallucination\_streak \+= 1, иначе hallucination\_streak \= 0;  
- флаг активен только если hallucination\_streak \>= HALLUCINATION\_PERSISTENCE.

Аналогичный гистерезис рекомендуется для geometric\_hallucination.

### 2.8. Симметричный Chamfer как вспомогательная метрика

В evaluate.py добавляется симметричная метрика расстояния между предсказанной и целевой бинарной маской.

Основная метрика:

symmetric\_chamfer\_error

Она штрафует и пропущенную массу, и лишнюю массу.

Определение:

symmetric\_chamfer\_error \= 0.5 \* (

    mean\_distance\_from\_pred\_to\_target

    \+ mean\_distance\_from\_target\_to\_pred

)

Практическая реализация через distance transform:

dt\_target \= distance\_transform\_edt(1 \- target\_mask)

dt\_pred \= distance\_transform\_edt(1 \- pred\_mask)

pred\_to\_target \= dt\_target\[pred\_mask\].mean() if pred\_mask.any() else large\_value

target\_to\_pred \= dt\_pred\[target\_mask\].mean() if target\_mask.any() else large\_value

symmetric\_chamfer\_error \= 0.5 \* (pred\_to\_target \+ target\_to\_pred)

**Нормировка:** результат делится на диагональ сетки sqrt(GRID\_SIZE\*\*2 \+ GRID\_SIZE\*\*2) для масштабно-инвариантности:

symmetric\_chamfer\_error \= symmetric\_chamfer\_error / (GRID\_SIZE \* math.sqrt(2))

Назначение:

- мониторинг качества сходимости кластеров к нужным центрам масс;  
- раннее обнаружение скрытых геометрических галлюцинаций;  
- не используется в loss.backward() в текущей версии.

⚠️ Обязательное правило для агента: в cognitive\_loop.py агент читает symmetric\_chamfer\_error наравне с β₀. Если β₀ совпадает с целевым, но symmetric\_chamfer\_error выше порога, агент фиксирует это как geometric\_hallucination.

Односторонний distance transform может сохраняться как диагностический, но не является основной метрикой геометрической галлюцинации.

⚠️ **Производительность:** distance\_transform\_edt из scipy.ndimage работает только на CPU и не поддерживает батчи. Для текущей конфигурации (батч 1–2, сетка 64×64) это допустимо. Если сетка или батч вырастут, необходимо переключиться на кастомную реализацию на PyTorch через torch.nn.functional.conv2d (approximate distance transform) или kornia.morphology.distance\_transform, чтобы избежать CPU/GPU ping-pong.

### 2.9. Нормировка порогов галлюцинаций

Пороги MSE\_HALLUCINATION\_THRESHOLD и SYMMETRIC\_CHAMFER\_HALLUCINATION\_THRESHOLD имеют смысл только при зафиксированной нормировке.

**MSE** вычисляется как среднее по всем пикселям и супервизируемым каналам (видимый \+ альфа):

mse \= F.mse\_loss(pred, target, reduction='mean')

Порог MSE\_HALLUCINATION\_THRESHOLD \= 0.05 относится к этому значению. При изменении числа каналов или нормировки порог должен быть пересчитан.

**Chamfer** нормируется на диагональ сетки (см. 2.8). Порог SYMMETRIC\_CHAMFER\_HALLUCINATION\_THRESHOLD \= 0.10 относится к нормированному значению.

⚠️ Оба порога должны быть задокументированы в config.py с формулами нормировки. При смене GRID\_SIZE пороги не «плывут» благодаря нормировке, но это должно быть проверено тестом.

## 3\. СЕМАНТИКА КАНАЛОВ СОСТОЯНИЯ

Состояние клетки — вектор из:

N\_CHANNELS \= 16

### 3.1. Tensor Layout

Во всех модулях проекта состояние хранится в формате (B, C, H, W) — channels-first.

Это означает:

- state\[:, c, :, :\] — доступ к каналу c;  
- state\[:, ALIVE\_CHANNEL, :, :\] — альфа-канал;  
- state\[:, STRESS\_CHANNEL:STRESS\_CHANNEL+1, :, :\] — срез стресс-канала;  
- маски имеют форму (B, 1, H, W) для broadcast по каналам.

Запрещено использовать channels-last (B, H, W, C) внутри модулей. Если внешний код требует другого порядка, конвертация выполняется на границе модуля.

### 3.2. Назначение каналов

| Канал | Назначение |
| :---- | :---- |
| 0 | Видимый канал / морфоген. Через sigmoid даёт изображение в диапазоне \[0, 1\] |
| 1 | Альфа-канал / alive-маска. Определяет живость клетки |
| 2–14 | Скрытые каналы внутренней памяти клетки и морфогенетических сигналов |
| 15 | Системный стресс-канал |

### 3.3. Интерпретационная дисциплина

- канал 0 контролируется через MSE видимого паттерна;  
- канал 1 контролируется через политику alive-маски, травму и регенерацию;  
- каналы 2–14 считаются внутренней рабочей памятью и полем для морфогенетических сигналов;  
- канал 15 является системным и не доступен для ручного INJECT\_MORPHOGEN.

### 3.4. Резервирование системных каналов

RESERVED\_SYSTEM\_CHANNELS \= \[15\]

Это означает:

- агент не может инжектить морфоген в канал 15;  
- стресс-канал обновляется системной динамикой;  
- модель может читать канал 15 как вход, но не управляет им напрямую.

### 3.5. Супервизия альфа-канала

Целевая маска включает альфа-канал.

При вычислении MSE:

- видимый канал 0 супервизируется по целевому изображению;  
- альфа-канал 1 супервизируется по целевой бинарной маске.

Это предотвращает ситуацию, когда модель рисует правильный паттерн в канале 0, но не формирует корректную alive-маску.

### 3.6. Единый source of truth для бинаризации

Для вычисления топологических метрик используется единая бинарная маска:

binary\_mask \= (

    (sigmoid(alpha\_raw) \> ALIVE\_THRESHOLD)

    & (sigmoid(visible) \> BINARY\_THRESHOLD)

)

Это единственная маска, по которой считается топология во всех модулях:

- topology.py;  
- bridge.py;  
- evaluate.py;  
- cognitive\_loop.py.

Запрещено использовать только альфа-канал или только видимый канал для топологических расчётов.

### 3.7. Область вычисления MSE

MSE вычисляется по всей сетке, включая мёртвые зоны, чтобы модель училась не только рисовать паттерн, но и гасить фон. Альфа-канал супервизируется по всей сетке аналогично.

## 5\. ПОЛИТИКА ALIVE-МАСКИ

### 5.1. Основной флаг

Модель имеет атрибут:

model.alive\_mask\_enabled: bool

Дефолт:

model.alive\_mask\_enabled \= True

Метода set\_iteration больше нет. Никаких \_current\_iteration быть не должно.

### 5.2. Порог жизни

ALIVE\_THRESHOLD \= 0.5

Клетка считается живой, если:

sigmoid(alpha\_raw) \> ALIVE\_THRESHOLD

Важно:

- сравнение строго больше;  
- sigmoid(0) \= 0.5;  
- 0.5 \> 0.5 — ложь;  
- обнулённая клетка мертва.

### 5.3. Устойчивость смерти

Если клетка:

- имеет alpha\_raw \= 0;  
- не имеет живых соседей;

то она остаётся мёртвой. Это корректное поведение.

### 5.4. Регенерация с границы раны

Если мёртвая клетка имеет живого соседа, она может быть восстановлена за счёт соседа. Это не считается ошибкой. Это ожидаемый механизм регенерации.

Важно различать:

- **плохое воскрешение:** мёртвое поле самопроизвольно оживает из\-за неправильного порога или пост-апдейтной маски;  
- **хорошая регенерация:** рана зарастает от живых границ.

### 5.5. Травма

При травме альфа-канал должен быть установлен в заведомо мёртвое значение:

DEAD\_ALPHA\_VALUE \= \-10.0

### 5.6. Warmup alive-маски

ALIVE\_WARMUP\_ITERS \= 50

Поведение:

- первые 50 итераций обучения маска выключена;  
- начиная с итерации 50 маска включается;  
- в момент перехода пул состояний полностью сбрасывается: pool.replace\_all\_fresh().

### 5.7. Загрузка чекпоинта

После загрузки чекпоинта:

model.alive\_mask\_enabled \= True

### 5.8. Правило pre-update alive-маски

Критическое правило:

> Alive-маска должна вычисляться только из состояния до обновления, то есть из state, а не из new\_state.

Смысл:

- клетка не может самопроизвольно ожить из полностью мёртвого поля;  
- обновление может получить только клетка, которая уже была живой до шага, либо имеет живого соседа до шага;  
- если клетка была мёртвой и не имела живых соседей до шага, её обновление должно быть запрещено.

### 5.9. Инвариант смерти после обучения

Недостаточно проверить, что мёртвое поле не оживает у необученной модели. Нужно проверять, что обученная модель не самовоспламеняется из мёртвого поля.

Минимальный тест:

- взять полностью нулевое или мёртвое состояние;  
- применить обученную модель в eval();  
- выполнить не менее 500 шагов;  
- убедиться, что живые клетки не возникают, если изначально живых соседей нет.

Этот тест должен быть частью пост-тренировочной проверки или расширенного smoke-теста.

### 5.10. Инвариант живого fresh-состояния

При вызове replace\_all\_fresh() или replace\_with\_fresh(index) создаваемое состояние обязано содержать живые клетки.

Причина: sigmoid(0) \= 0.5, 0.5 \> 0.5 \= False → нулевая клетка мертва. Если fresh-состояние — нули или шум с медианой ≤ 0 в альфа-канале, то в момент включения маски вся сетка мертва без живых соседей → маска из pre-update state замораживает смерть навсегда.

Инвариант:

def \_validate\_fresh\_state(state):

    alive\_fraction \= (

        torch.sigmoid(state\[:, ALIVE\_CHANNEL, :, :\]) \> ALIVE\_THRESHOLD

    ).float().mean()

    assert alive\_fraction \>= FRESH\_MIN\_ALIVE\_FRACTION, (

        f"Fresh state has {alive\_fraction:.2%} alive cells, "

        f"need \>= {FRESH\_MIN\_ALIVE\_FRACTION:.2%}"

    )

Параметр:

FRESH\_MIN\_ALIVE\_FRACTION \= 0.20

Реализация fresh-состояния:

- шум инициализации с уровнем INIT\_NOISE\_LEVEL;  
- альфа-канал инициализируется так, чтобы гарантировать ≥ 20% живых клеток;  
- канал 15 инициализируется нулями.

## 6\. ПОЛИТИКА СТРЕСС-КАНАЛА И СТРЕСС-ШЕРИНГА

### 6.1. Смысл стресс-канала

Стресс-канал — это системное диффузное поле девиации/пластичности, условно называемое стрессом.

Это не поле статической ошибки.

Он отражает:

- локальную необычность изменения состояния;  
- отклонение текущей динамики от недавнего скользящего среднего;  
- возможную зону регенерации, перестройки или повреждения;  
- упрощённый аналог координационного сигнала, похожего на медленный морфогенетический фон или биоэлектрическую модуляцию.

Он нужен для:

- улучшения регенерации;  
- координации границ;  
- выявления проблемных зон;  
- мягкой модуляции локальной динамики;  
- мониторинга перегрузки системы.

⚠️ **Важная честная оговорка:** если система сошлась в неверную статическую конфигурацию, стресс может быть близок к нулю, потому что изменения состояния малы. Поэтому стресс в текущей версии **слеп к статическим топологическим и геометрическим ошибкам**. Для их обнаружения используются β₀, β₁, symmetric\_chamfer\_error и агентские эвристики.

⚠️ **Информационный характер:** влияние стресса на local\_dt при текущих параметрах не превышает \+10% шага (см. раздел 1.6). Основная ценность стресс-канала — информационная (входной контекст для CellBrain), а не темпоральная.

⚠️ **Известное ограничение (gameable signal):** стресс-вход считается из |delta| самой модели. Теоретически сеть может научиться маскировать или генерировать девиации. Контроль STRESS\_SHUFFLE\_MODE частично ловит это, но полностью не исключает. Зафиксировано как ограничение в отчётах.

### 6.2. Базовые параметры

STRESS\_ENABLED \= True

STRESS\_CHANNEL \= 15

STRESS\_INPUT\_GAIN \= 0.15

STRESS\_DECAY \= 0.05

STRESS\_DIFFUSION \= 0.20

STRESS\_MAX \= 3.0

STRESS\_AFFECTS\_DT \= True

STRESS\_TEMP\_SCALE \= 0.10

DT\_MAX\_EFFECTIVE \= 0.5

STRESS\_EMA\_ALPHA \= 0.95

STRESS\_ABLATION\_MODE \= False

STRESS\_SHUFFLE\_MODE \= False

STRESS\_TARGET\_ERROR\_MODE \= False

STRESS\_COMPRESS\_INPUT \= False  \# Rev.7: опциональная компрессия

⚠️ Обоснование снижения STRESS\_INPUT\_GAIN: стационарное решение s\* \= GAIN \* x / DECAY. При GAIN \= 1.0, DECAY \= 0.05 коэффициент усиления \= 20\. Девиация порядка 0.15 уже насыщает канал у STRESS\_MAX \= 3.0. При GAIN \= 0.15 коэффициент усиления \= 3, что даёт рабочий диапазон.

Если пилотные прогоны покажут, что стресс слишком слаб, допустимо поднять до 0.3, но не выше 0.5 без повторного анализа насыщения.

⚠️ **Риск насыщения:** при любом устойчивом девиационном входе ≥ \~1.0 канал прибивается к потолку STRESS\_MAX \= 3.0 и становится неинформативен именно тогда, когда наиболее интересен. Guard saturation\_fraction отслеживает это, но не устраняет причину.

### 6.3. Опциональная компрессия входа стресса

Для снижения риска насыщения при больших девиациях вводится опциональная компрессия:

STRESS\_COMPRESS\_INPUT \= False  \# по умолчанию выключена

Если включена:

stress\_input \= torch.log1p(clamp(delta\_norm \- stress\_ema, 0.0, None))

stress\_input \= clamp(stress\_input, 0.0, STRESS\_MAX)

Это сжимает большие девиации и расширяет рабочий диапазон канала. Режим является диагностическим и не включается в базовые эксперименты без явного обоснования.

### 6.4. Что читает стресс-канал

Стресс-канал доступен клетке как входной признак. Модель может научиться использовать его через CellBrain.

Но:

- модель не управляет стресс-каналом напрямую;  
- стресс-канал обновляется внешним системным правилом;  
- стресс-канал не участвует в потере напрямую.

### 6.5. Правило обновления стресса

На каждом шаге:

1. Вычисляется локальная величина стресса из девиации нормы изменения состояния относительно EMA.  
2. Стресс затухает со временем.  
3. Стресс диффундирует к соседям.  
4. Стресс обрезается диапазоном \[0, STRESS\_MAX\].  
5. Стресс обнуляется для изолированных мёртвых клеток.

#### 6.5.1. Разрыв петли положительной обратной связи

Проблема: если стресс считается из абсолютной величины |delta|, а local\_dt растёт со стрессом, возникает петля: стресс растёт → dt растёт → delta растёт → стресс растёт.

Решение: стресс считается из девиации относительно скользящего среднего:

stress\_ema \= STRESS\_EMA\_ALPHA \* stress\_ema \+ (1 \- STRESS\_EMA\_ALPHA) \* delta\_norm\_mean

stress\_input \= clamp(delta\_norm \- stress\_ema, 0.0, STRESS\_MAX)

stress \= stress \* (1 \- STRESS\_DECAY) \+ STRESS\_INPUT\_GAIN \* stress\_input

⚠️ **Инерция EMA.**

При обновлении каждый симуляционный шаг и STRESS\_EMA\_ALPHA \= 0.95 эффективное окно сглаживания составляет примерно:

1 / (1 \- 0.95) \= 20 шагов

Это десятки шагов, а не сотни. Если нужна более длинная память, необходимо либо обновлять EMA реже, например раз в отчёт, либо увеличить STRESS\_EMA\_ALPHA, например до 0.99. В текущей версии по умолчанию EMA обновляется каждый симуляционный шаг.

После резкого вмешательства delta\_norm может подскочить, а EMA будет догонять несколько десятков шагов. Агент должен учитывать stress\_derivative. Если стресс высок, но stress\_derivative \< 0, система успокаивается, и агент не должен тратить бюджет на вмешательства.

#### 6.5.2. Исключение канала 15 из расчёта стресса

При вычислении delta\_norm для стресса канал 15 исключается. Иначе стресс частично разгоняет сам себя через собственное изменение.

delta\_for\_stress \= delta.clone()

delta\_for\_stress\[:, STRESS\_CHANNEL, :, :\] \= 0.0

delta\_norm \= delta\_for\_stress.abs().mean(dim=1, keepdim=True)

#### 6.5.3. Исключение мёртвых изолированных клеток из стресс-статистик

Стресс считается после применения life\_support\_mask. Клетки, которые фактически не обновляются, не должны вносить вклад в stress\_input и stress\_ema.

delta\_masked \= delta \* life\_support\_mask.float()

delta\_for\_stress \= delta\_masked.clone()

delta\_for\_stress\[:, STRESS\_CHANNEL, :, :\] \= 0.0

delta\_norm \= delta\_for\_stress.abs().mean(dim=1, keepdim=True)

#### 6.5.4. Опциональные диагностические источники стресса

Для проверки того, что стресс-канал содержит полезную пространственную информацию, а не просто является лишним входным каналом, вводятся два опциональных режима.

##### 6.5.4.1. Пространственно перемешанный стресс

STRESS\_SHUFFLE\_MODE \= False

Если режим включён:

- stress\_input вычисляется как обычно;  
- затем пространственно перемешивается случайной перестановкой или фиксированным шумовым отображением;  
- глобальная статистика сигнала сохраняется;  
- локальная пространственная информация разрушается.

Назначение:

- отличить «информацию в поле» от «просто лишнего входного канала»;  
- если стресс включён лучше, чем перемешанный стресс, это аргумент в пользу полезности пространственного сигнала;  
- если разницы нет, эффект может объясняться неспецифическим контекстом.

##### 6.5.4.2. Стресс на основе локальной ошибки относительно цели

STRESS\_TARGET\_ERROR\_MODE \= False

Если режим включён:

- стресс может вычисляться из локального несоответствия текущей бинарной маски целевой маске;  
- допускается использовать локальный сглаженный mismatch или нормированный симметричный chamfer-прокси;  
- этот режим является диагностическим и не считается биологически достоверным по умолчанию, потому что использует знание цели.

Назначение:

- проверить, устраняет ли явный сигнал ошибки слепоту девиационного стресса к статическим ошибкам;  
- использовать как отдельную абляцию, а не как основной режим.

Ограничение:

STRESS\_SHUFFLE\_MODE и STRESS\_TARGET\_ERROR\_MODE не должны быть включены одновременно в базовых экспериментах, если явно не проектируется гибридное исследование.

### 6.6. Защита от самовоскрешения через стресс

Стресс-канал:

- не изменяет альфа-канал напрямую;  
- не может сам оживить мёртвую клетку без живых соседей;  
- подчиняется той же логике жизни, что и остальная система.

### 6.7. Влияние стресса на динамику

Если STRESS\_AFFECTS\_DT \= True, локальный эффективный шаг времени может слегка меняться в зонах стресса:

stress\_norm \= stress / STRESS\_MAX

local\_dt \= DT \* (1.0 \+ STRESS\_TEMP\_SCALE \* stress\_norm)

local\_dt \= clamp(local\_dt, DT, DT\_MAX\_EFFECTIVE)

Смысл:

- зона стресса получает чуть больше пластичности;  
- система может быстрее выходить из локальных ошибок;  
- без взрыва динамики.

⚠️ **Реальный масштаб эффекта:** при DT \= 0.1 и STRESS\_TEMP\_SCALE \= 0.10 максимальное увеличение составляет 0.1 \* 0.10 \= 0.01, то есть шаг растёт с 0.1 до 0.11. При DT ≥ 0.45 эффект полностью поглощается клампом DT\_MAX\_EFFECTIVE \= 0.5. Влияние стресса на динамику — преимущественно информационное (входной канал), а не темпоральное.

Примечание: при использовании варианта с девиацией от EMA петля обратной связи разорвана, и положительное влияние стресса на DT безопасно.

Резервный вариант, если девиация нестабильна:

local\_dt \= DT \* (1.0 \- STRESS\_TEMP\_SCALE \* stress\_norm)

local\_dt \= clamp(local\_dt, DT \* 0.5, DT)

В текущей версии по умолчанию используется вариант с девиацией. Вариант с инверсией — как резервный.

### 6.8. Градиентная политика стресса

Для устойчивости:

- обновление стресс-канала выполняется как системный недифференцируемый процесс;  
- стресс передаётся в модель как вход, но его собственное обновление не должно ломать градиенты обучения.

Рекомендуется:

- рассчитывать стресс в torch.no\_grad();  
- использовать его как внешний контекст;  
- stress\_ema хранится как буфер модели, не как параметр.

⚠️ Загрузка старых чекпоинтов:

- если чекпоинт не содержит stress\_ema, загрузка выполняется с strict=False;  
- stress\_ema инициализируется нулём;  
- это состояние должно быть явно залогировано как stress\_ema cold start;  
- после загрузки чекпоинта без stress\_ema рекомендуется короткий прогрев стресс-статистик перед ответственными измерениями;  
- если N\_CHANNELS чекпоинта ≠ N\_CHANNELS модели, чекпоинт помечается как несовместимый и не загружается без явной конвертации.

### 6.9. Граничные условия для стресса

Критическое разделение физики:

Для восприятия и alive-маски используется:

BOUNDARY\_MODE \= "constant"

Для диффузии стресса используется:

F.pad(..., mode='reflect')

Причина: биологическая ткань не обрывается в «абсолютный ноль напряжения». Если края будут стоками, стресс будет искусственно скапливаться в центре сетки и обнуляться на периферии.

Пример:

\# Для восприятия и alive-маски:

x\_padded \= F.pad(x, (1,1,1,1), mode='constant', value=0)

\# Для диффузии стресса:

stress\_padded \= F.pad(stress, (1,1,1,1), mode='reflect')

### 6.10. Инициализация стресс-канала

В init\_state и во всех fresh-состояниях канал 15 инициализируется нулями:

state\[:, STRESS\_CHANNEL, :, :\] \= 0.0

### 6.11. Обязательная оговорка

Стресс-канал в текущей версии — это прокси-механизм, а не полноценная физическая симуляция биоэлектрического поля.

Он не является симуляцией:

- ионных каналов;  
- мембранных потенциалов;  
- электрофизиологии ткани.

Это именно информационный координационный сигнал.

### 6.12. Абляция стресс-канала

Стресс-шеринг — главная научная новинка версии. Без парных прогонов утверждение «стресс помогает регенерации» будет ненаучным.

Требование:

- эксперименты E02 и E03 запускаются парно: STRESS\_ENABLED=True и STRESS\_ENABLED=False;  
- при STRESS\_ENABLED=False канал 15 остаётся в архитектуре, но заполняется нулями и не обновляется;  
- прогонки выполняются на одних и тех же сидах;  
- минимальное число сидов: 6;  
- рекомендуемое число сидов: 10;  
- **для подтверждающего прогона (не пилота): 10–15 сидов;**  
- статистический тест: парный тест Уилкоксона;  
- для малых выборок использовать точный тест, если доступно;  
- метрики сравнения: медианный recovery\_steps, stress\_peak\_after\_injury, intervention\_count, symmetric\_chamfer\_error;  
- **обязательны: доверительные интервалы или межквартильные размахи;**  
- **обязательны: effect size (например, rank-biserial correlation или Cohen's d для парных выборок);**  
- **обязательны: bootstrap CI для медианной разницы (минимум 10000 ресемплирований).**

⚠️ Статистическая причина минимума 6 сидов: при парном тесте Уилкоксона и n \= 5 минимально возможный двусторонний p-value равен 2 / 2^5 \= 0.0625, то есть требование p \< 0.05 недостижимо. При n \= 6 минимальный двусторонний p-value равен 2 / 2^6 \= 0.03125.

⚠️ **Мощность:** n \= 6 — это пилот, не подтверждение. Минимально достижимый p ≠ достаточная мощность. Для эффекта «−20% recovery\_steps» при межсидовой дисперсии 6 пар, скорее всего, не хватит для уверенного обнаружения. Пилот на 6 сидах определяет направление; подтверждающий прогон на 10–15 сидах фиксирует результат.

Фальсифицируемая гипотеза:

> «Стресс-канал снижает медианный recovery\_steps на ≥20% на ≥6 сидах против 15-канального нулевого базлайна при прочих равных условиях. Проверка: парный тест Уилкоксона, p \< 0.05».

⚠️ Нулевой результат тоже результат. Если абляция не покажет разницы, это фиксируется как:

> «Сеть не использует инженерный стресс-сигнал; гипотеза о пользе стресс-шеринга не подтверждена в текущей архитектуре».

Рекомендуемые расширенные абляции:

- STRESS\_SHUFFLE\_MODE=True;  
- STRESS\_TARGET\_ERROR\_MODE=True.

Если ресурсы ограничены, обязательна только пара stress on/off. Расширенные абляции выполняются после базового подтверждения эффекта.

STRESS\_ABLATION\_MODE \= False

### 6.13. Инвариант парности сидов

⚠️ **Критический инвариант абляции:**

Парный тест Уилкоксона осмыслен только если сид жёстко задаёт:

- инициализацию весов модели;  
- инициализацию состояний пула;  
- стохастический апдейт (UPDATE\_PROB);  
- ресеты пула (STATE\_RESET\_PROB);  
- любые другие случайные операции.

При этом два арма абляции (STRESS\_ENABLED=True и STRESS\_ENABLED=False) на одном и том же сиде должны отличаться **только** наличием или отсутствием обновления стресс-канала. Все остальные источники энтропии идентичны.

Это должно быть реализовано через передачу одного и того же torch.Generator в оба арма и зафиксировано как инвариант в experiment\_manager.py.

### 6.14. Наблюдаемые стресс-метрики для агента

В наблюдения агента включаются:

stress\_mean

stress\_max

stress\_derivative \= stress\_mean\_current \- stress\_mean\_previous\_report

saturation\_fraction \= (stress \> 0.9 \* STRESS\_MAX).float().mean()

stress\_mode

Правила:

- stress\_derivative \< 0 при высоком стрессе → система успокаивается, не вмешиваться;  
- saturation\_fraction \> 0.5 → стресс-канал насыщен, сигнал бесполезен, логировать как предупреждение.

## 7\. ПОЛИТИКА ОТЧЁТНОСТИ В КОГНИТИВНОМ ЦИКЛЕ

### 7.1. Основной шаг цикла

Основной цикл когнитивного контура использует:

STEP\_SIZE \= 10

Отчёты создаются строго при:

step % report\_interval \== 0

Минимальный рекомендуемый и обязательный по умолчанию report\_interval:

COGNITION\_REPORT\_INTERVAL \= 20

### 7.2. Отдельный счётчик фактической симуляции

Добавляется отдельный счётчик:

sim\_step

Он отражает реальное количество выполненных шагов симуляции.

Пример:

- основной цикл сделал 10 шагов: step \+= 10, sim\_step \+= 10;  
- агент выбрал CONTINUE\_TRAINING на 30 шагов: sim\_step \+= 30, но step не меняется.

### 7.3. Поведение CONTINUE\_TRAINING

Критическое правило:

> CONTINUE\_TRAINING НЕ сдвигает step.

Дополнительные шаги симуляции выполняются между отчётами, но не ломают расписание.

Правильно:

if extra \> 0:

    current\_state \= run\_steps\_no\_grad(model, current\_state, steps=extra)

    sim\_step \+= extra

    \# step НЕ меняется

Неправильно:

step \+= extra

### 7.4. Ограничение дополнительных шагов

Чтобы сохранить предсказуемость отчётов:

extra \= min(requested\_steps, MAX\_EXTRA\_STEPS\_PER\_REPORT, report\_interval \- 1\)

Рекомендуемые значения:

MAX\_EXTRA\_STEPS\_PER\_REPORT \= 500

COGNITION\_REPORT\_INTERVAL \= 20

⚠️ **Семантика:** при report\_interval \= 20 фактический максимум дополнительных шагов ограничен report\_interval \- 1 \= 19. Параметр MAX\_EXTRA\_STEPS\_PER\_REPORT \= 500 является верхним пределом запроса агента, но фактическое исполнение ограничено остатком до следующего отчёта. Параметр переименован из MAX\_CONTINUE\_STEPS для ясности.

Если report\_interval меньше 2 \* STEP\_SIZE, это считается дефектом конфигурации.

### 7.5. Требование к report\_interval

report\_interval должен быть кратен STEP\_SIZE и не меньше 2 \* STEP\_SIZE.

Если STEP\_SIZE \= 10, допустимы:

20, 30, 40, 50, 100

Если передано значение 10, его следует автоматически повысить до 20 и записать предупреждение в лог.

### 7.6. Отчёты и длинные пробы

Длинные пробы, например MAINTENANCE\_WINDOW, AGING\_STEPS, не должны ломать расписание когнитивного цикла.

Поэтому:

- внутри регулярного когнитивного цикла разрешены только короткие проверки;  
- длинные пробы выполняются как отдельные эксперименты или офлайн-тесты.

### 7.7. Счётчик пула состояний

pool.maybe\_reset(sim\_step)

Привязка к sim\_step, а не к step, предотвращает рассинхронизацию ресетов пула с реальной динамикой при использовании CONTINUE\_TRAINING.

## 8\. ПОЛИТИКА ДЕЙСТВИЙ АГЕНТА И ЭКОНОМИКА ВМЕШАТЕЛЬСТВ

### 8.1. Допустимые действия

Список действий:

- MODIFY\_DT  
- MODIFY\_LR  
- MODIFY\_L1\_REG  
- MODIFY\_TARGET\_B0  
- CONTINUE\_TRAINING  
- APPLY\_INJURY  
- INJECT\_MORPHOGEN  
- STOP

Новых действий в текущей версии не добавляем, чтобы не раздувать код. Вся сила достигается через улучшение экономики, памяти и стратегий.

### 8.2. MODIFY\_DT

Изменяет шаг времени:

DT ∈ \[0.01, 0.5\]

Применяется немедленно:

- в config.DT;  
- в model.dt.

Откат возможен, если метрики ухудшились.

⚠️ **Детализация отката (Rev.7):**

При применении MODIFY\_DT сохраняются:

rollback\_state \= {

    "config\_dt": config.DT,

    "model\_dt": model.dt,

    "mse\_before": current\_mse,

    "b0\_before": current\_b0,

    "b1\_before": current\_b1,

    "chamfer\_before": current\_chamfer,

    "step\_applied": step,

    "sim\_step\_applied": sim\_step

}

По истечении GRACE\_WINDOW шагов сравниваются:

mse\_after \> mse\_before \+ 0.05  → откат

abs(b0\_after \- target\_b0) \> abs(b0\_before \- target\_b0) \+ 2  → откат

Если GRACE\_WINDOW пересекает границу отчёта, откат выполняется на ближайшем отчёте после завершения GRACE\_WINDOW, но не позже следующего отчёта.

### 8.3. MODIFY\_LR

Изменяет learning rate:

LR ∈ \[1e-5, 1e-2\]

Фаза без оптимизатора:

- изменение не применяется к config;  
- значение сохраняется в память как заявка для будущего обучения;  
- действие помечается как effective \= False;  
- note \= "no optimizer, saved as pending request".

Фаза с оптимизатором:

- значение применяется ко всем param\_groups;  
- действие помечается как effective \= True.

Откат применяется только в фазе обучения и только к значению в optimizer.param\_groups.

### 8.4. MODIFY\_L1\_REG

Изменяет вес L1-регуляризации:

L1\_REG\_WEIGHT ∈ \[0.0, 0.1\]

В фазе без обучения:

- не влияет на инференс;  
- сохраняется как заявка;  
- effective \= False;  
- не откатывается.

В фазе обучения:

- реально влияет на лосс;  
- effective \= True.

### 8.5. MODIFY\_TARGET\_B0

Изменяет целевое число кластеров:

TARGET\_COMPONENTS ∈ \[1, 10\]

Фаза без обучения:

- это заявка на будущее;  
- разрешено изменить цель и пересоздать целевую маску;  
- запрещено немедленно запускать дообучение, если фаза не поддерживает обучение;  
- откатывать сам факт смены цели запрещено.

Нужно установить флаг:

pending\_retraining \= True

### 8.6. CONTINUE\_TRAINING

Дополнительные шаги симуляции без изменения step.

Параметр:

steps ∈ \[1, 500\]

Но фактическое значение ограничено:

min(requested, MAX\_EXTRA\_STEPS\_PER\_REPORT, report\_interval \- 1\)

⚠️ **Риск доминирования:** CONTINUE\_TRAINING бесплатен (cost \= 0.0). Без явной формулы полезности агент может всегда выбирать «ничего не делать». Для предотвращения этого вводится формула utility-скора (см. 8.13).

### 8.7. APPLY\_INJURY

Нанести травму.

Параметр:

size ∈ \[4, 32\]

Требования:

- травма должна быть привязана к целевому паттерну, если он есть;  
- если целевых кластеров несколько, выбирается один случайный кластер;  
- если кластеров нет, травма наносится в центр сетки;  
- альфа-канал в зоне травмы устанавливается в DEAD\_ALPHA\_VALUE.

Дополнительно:

- если травма не изменила β₀, допускается одна повторная попытка с увеличенным размером;  
- повторный размер не должен превышать 32;  
- если травма всё равно не повлияла на топологию, событие логируется как injury\_ineffective.

### 8.8. STOP

Останавливает когнитивный цикл.

После STOP:

- создаётся итоговый отчёт;  
- состояние сохраняется в память;  
- цикл завершается.

### 8.9. INJECT\_MORPHOGEN

Цель действия:

- агент не просто меняет глобальные гиперпараметры;  
- агент действует как биологический эндокринный контур;  
- агент вводит локальный морфогенетический сигнал в скрытые каналы состояния.

Параметры:

x ∈ \[0, GRID\_SIZE \- 1\]

y ∈ \[0, GRID\_SIZE \- 1\]

radius ∈ \[1, 16\]

channel ∈ \[2, 14\]

value ∈ \[-3.0, 3.0\]

Поведение:

- в круге радиуса radius вокруг точки (x, y) изменяется указанный скрытый канал;  
- изменение должно быть мягким, через затухание по расстоянию;  
- видимый канал 0 и альфа-канал 1 напрямую этим действием не изменяются;  
- системный канал 15 недоступен для инъекций;  
- действие не ломает расписание отчётов;  
- действие считается экспериментальным вмешательством, а не обучением весов.

Если координаты не указаны:

- выбирается центр наибольшего живого кластера;  
- если кластеров нет, выбирается центр сетки.

Смысл:

- INJECT\_MORPHOGEN позволяет агенту сдвигать локальный аттрактор;  
- это шаг к управлению ландшафтом Уоддингтона;  
- это лучше, чем только крутить DT или LR.

### 8.10. Бюджет и стоимость вмешательств

Это ключевой механизм агента. Агент должен минимизировать не только ошибку системы, но и стоимость собственного воздействия.

#### 8.10.1. Разделение бюджетов

Вводятся два типа ограничений:

АТР-бюджет:

INTERVENTION\_BUDGET\_PER\_REPORT \= 2.0

Лимит целостности:

INJURY\_COOLDOWN\_REPORTS \= 5

APPLY\_INJURY — это не «улучшение», а эксперимент над тканью. Он не списывается с АТР-бюджета, но имеет жёсткий глобальный кулдаун.

#### 8.10.2. Стоимость действий

ACTION\_COSTS \= {

    "CONTINUE\_TRAINING": 0.0,

    "MODIFY\_DT": 0.10,

    "MODIFY\_LR": 0.10,

    "MODIFY\_L1\_REG": 0.10,

    "MODIFY\_TARGET\_B0": 0.20,

    "INJECT\_MORPHOGEN": 0.5,

    "APPLY\_INJURY": 0.0,

    "STOP": 0.0

}

INTERVENTION\_COST\_WEIGHT \= 0.1 — это utility-штраф в скоре агента, а не жёсткий бюджет.

#### 8.10.3. Нормированная доза морфогена

Для INJECT\_MORPHOGEN считается нормированная доза:

normalized\_dose \= sum(abs(delta\_hidden\_channels)) / (

    affected\_cells \* num\_affected\_channels \* max\_allowed\_value

)

Полная стоимость морфогена:

morphogen\_cost \= 0.5 \+ 0.5 \* normalized\_dose

Максимальная полная стоимость одной инъекции: 1.0.

При бюджете 2.0 и MORPHOGEN\_COOLDOWN\_REPORTS \= 1 агент не может сделать две инъекции за один отчёт.

При кулдауне 1 допустимый сценарий:

- одна инъекция морфогена стоимостью до 1.0;  
- плюс, при остатке бюджета, другое дешёвое действие, например MODIFY\_DT.

Две инъекции за один отчёт запрещены по умолчанию.

Если доза превышает остаток бюджета:

- действие отклоняется;  
- агенту предлагается выбрать меньший радиус или меньшее значение.

#### 8.10.4. Правило минимального вмешательства

Если ожидаемая польза действия ниже порога, агент обязан выбрать:

CONTINUE\_TRAINING

#### 8.10.5. Кулдаун морфогена

MORPHOGEN\_COOLDOWN\_REPORTS \= 1

MORPHOGEN\_MAX\_INJECTIONS\_PER\_REPORT \= 1

⚠️ **Явная семантика (Rev.7):**

Условие разрешения инъекции:

allowed \= (current\_report\_number \- last\_morphogen\_report\_number) \> MORPHOGEN\_COOLDOWN\_REPORTS

При MORPHOGEN\_COOLDOWN\_REPORTS \= 1: инъекция на отчёте N разрешена, если последняя инъекция была на отчёте ≤ N−2. То есть между двумя инъекциями проходит минимум один полный отчётный интервал.

Если MORPHOGEN\_COOLDOWN\_REPORTS \= 0: инъекции разрешены на каждом отчёте, но не более MORPHOGEN\_MAX\_INJECTIONS\_PER\_REPORT за отчёт.

Если требуется более агрессивная политика, можно уменьшить кулдаун до 0, но это должно быть явно оправдано, залогировано и ограничено бюджетом.

#### 8.10.6. Кулдаун травмы

INJURY\_COOLDOWN\_REPORTS \= 5

Агент не может наносить травму чаще, чем раз в 5 отчётов. Это предотвращает ситуацию, где агент превращается в садиста, постоянно ломающего систему ради проверки регенерации.

#### 8.10.7. Единый валидатор вмешательств

Все проверки:

- АТР-бюджета;  
- стоимости действия;  
- нормированной дозы морфогена;  
- кулдауна морфогена;  
- кулдауна травмы;  
- зарезервированных каналов;  
- диапазонов параметров;  
- максимально допустимого числа инъекций за отчёт

должны выполняться одним модулем или одной функцией, например:

cognition/action\_validator.py

Запрещено размазывать проверки бюджета между bridge.py, cognitive\_loop.py и agent\_backends.py.

### 8.11. Калибровка морфогенетических каналов

Перед активным использованием INJECT\_MORPHOGEN рекомендуется выполнить калибровочный протокол.

Цель калибровки: понять, какие скрытые каналы стабилизируют, дестабилизируют, влияют на плотность, топологию, или почти нейтральны.

Протокол:

1. Взять стабильное состояние.  
2. Ввести малую дозу в выбранный канал.  
3. Прогнать короткое число шагов, например 20–30.  
4. Записать:  
   - изменение плотности;  
   - изменение β₀;  
   - изменение β₁;  
   - изменение MSE;  
   - изменение symmetric\_chamfer\_error;  
   - изменение стресса;  
   - скорость возврата.  
5. Повторить для небольшого набора каналов.

Ограничение из\-за железа:

- не более 3 каналов за одну калибровку;  
- не более 30 шагов на канал;  
- только в eval() и без градиентов.

⚠️ **Предупреждение:** калибровка может быть шумной. Интерпретации вида «weak stabilizing effect, confidence 0.42» не следует принимать как руководство к действию без повторной проверки. Калибровочные записи — это предварительные наблюдения, не доказательства.

Память калибровок:

{

    "channel": 5,

    "dose": 0.12,

    "radius": 4,

    "effect\_density": \-0.02,

    "effect\_b0": 0,

    "effect\_b1": 0,

    "effect\_mse": \-0.01,

    "effect\_chamfer": \-0.008,

    "effect\_stress": \-0.03,

    "recovery\_steps": 18,

    "interpretation": "weak stabilizing effect",

    "confidence": 0.42,

    "valid\_for": {

        "checkpoint\_id": "nca\_e02\_best.pt",

        "target\_topology": {"b0": 3, "b1": 0, "chi": 3}

    }

}

Инвалидация калибровки: после смены цели или загрузки другого чекпоинта калибровка каналов 2–14 становится невалидной.

### 8.12. Иерархия вмешательств агента

Агент обязан следовать принципу минимального вмешательства:

1. Если система стабильна и близка к цели — не вмешиваться.  
2. Если динамика медленно улучшается — выбрать CONTINUE\_TRAINING.  
3. Если нужен мягкий сдвиг — использовать INJECT\_MORPHOGEN.  
4. Если динамика слишком медленная или затухающая — менять DT.  
5. Если нужно проверить устойчивость — использовать APPLY\_INJURY.  
6. Если обучение доступно — менять LR и регуляризацию.  
7. При катастрофической нестабильности — STOP.

### 8.13. Формула utility-скора агента

⚠️ **Обязательная формула (Rev.7):**

Для предотвращения доминирования бесплатного CONTINUE\_TRAINING агент вычисляет ожидаемую полезность каждого действия:

utility \= expected\_metric\_improvement \- INTERVENTION\_COST\_WEIGHT \* action\_cost

Где expected\_metric\_improvement — оценка ожидаемого улучшения целевой метрики (например, снижение symmetric\_chamfer\_error или |b0 \- target\_b0|) на основе истории предыдущих аналогичных действий из memory/.

Правило:

- если max(utility для всех действий) \< MIN\_UTILITY\_THRESHOLD, агент выбирает CONTINUE\_TRAINING;  
- если CONTINUE\_TRAINING выбирается более MAX\_CONSECUTIVE\_CONTINUE отчётов подряд при ненулевой ошибке, агент обязан рассмотреть INJECT\_MORPHOGEN или MODIFY\_DT.

MIN\_UTILITY\_THRESHOLD \= 0.005

MAX\_CONSECUTIVE\_CONTINUE \= 5

Формула utility-скора должна быть задокументирована в cognition/agent\_backends.py и проверяться в action\_validator.

### 8.14. Правило «Ленивый Агент»

⚠️ **Жёсткое правило (Rev.7):**

Если symmetric\_chamfer\_error высок (выше порога), а stress\_mean низок (ниже 0.2 \* STRESS\_MAX), это означает **статическую геометрическую ошибку**, которую стресс не видит.

В этом случае агент **ОБЯЗАН**:

1. Не ждать стресс-сигнала.  
2. Использовать INJECT\_MORPHOGEN в зоны максимального локального Chamfer-расхождения (если морфоген доступен и бюджет позволяет).  
3. Либо использовать STRESS\_TARGET\_ERROR\_MODE в диагностических целях.  
4. Зафиксировать в memory/discoveries.md: «Статическая геометрическая ошибка не обнаружена стрессом; вмешательство основано на symmetric\_chamfer\_error».

Это правило записывается в промпт для RuleBasedAgentV2 и в SYSTEM\_PROMPT для LLM.

### 8.15. Запрет агенту быть внешним художником

Агенту запрещено:

- напрямую перерисовывать целевую форму через канал 0;  
- напрямую устанавливать живой канал 1;  
- копировать целевую маску в состояние;  
- принудительно устанавливать β₀;  
- использовать системный стресс-канал для ручных инъекций.

Разрешено:

- мягко менять скрытые каналы;  
- менять динамику;  
- создавать условия для регенерации;  
- наблюдать и интерпретировать.

### 9.2. Разделение вычислительных ресурсов

- NCA-симуляция: на GPU, если доступен.  
- Когнитивный агент: строго на CPU.  
- Топологические вычисления: строго на CPU.  
- Локальная LLM: только на CPU и только если не вызывает OOM.

⚠️ Передача тензоров: при вычислении топологии на CPU используется:

tensor.to('cpu', non\_blocking=True)

### 9.3. Асинхронность CPU/GPU и защита от простоев

⚠️ **Критическое требование (Rev.7):**

Топология (scipy.ndimage.label) и агент работают на CPU. NCA работает на GPU. Синхронный tensor.to('cpu') внутри горячего цикла симуляции вызывает **столл GPU**: GPU простаивает, ожидая завершения передачи и обработки на CPU.

Требования:

1. Метрики топологии для отчётов считаются **не на каждом шагу sim\_step**, а только при наступлении step % report\_interval \== 0.  
2. Передача тензора на CPU выполняется с non\_blocking=True:  
     
   state\_cpu \= state.to('cpu', non\_blocking=True)  
     
   Расчёт начинается только после фактической материализации тензора (через torch.cuda.synchronize() или проверку готовности).  
     
3. Для тяжёлых операций (подсчёт топологии, Chamfer, label) рекомендуется использовать multiprocessing.Process или concurrent.futures.ProcessPoolExecutor с очередью, чтобы не блокировать основной поток симуляции.  
4. asyncio допустим для координации, но тяжёлые CPU-вычисления (scipy, numpy) должны быть в отдельном процессе из\-за GIL.  
5. Запрещено вызывать scipy.ndimage.label синхронно внутри forward() или в каждом шаге sim\_step.

#### 12.2.2. Pre-update alive-маска

В forward:

1. сначала вычисляется восприятие и delta;  
2. затем, если alive\_mask\_enabled, вычисляется alive-маска из исходного state;  
3. вычисляется life\_support\_mask \= alive\_pre | neighbor\_alive\_pre;  
4. delta \= delta \* life\_support\_mask — критическая строка;  
5. только после этого new\_state \= state \+ local\_dt \* delta;  
6. затем применяется clamp;  
7. запрещается вычислять alive-маску из new\_state.

#### 12.2.3. Граничный режим

PerceptionLayer обязан использовать BOUNDARY\_MODE из config.

Основной режим:

BOUNDARY\_MODE \= "constant"

Для диффузии стресса используется reflect.

#### 12.2.4. Обновление стресс-канала и динамики

Исправленный псевдокод:

\# \=== Всегда вычисляем life\_support\_mask из pre-update state \===

alive\_pre \= compute\_alive\_mask(state)

neighbor\_alive\_pre \= neighbor\_alive\_mask(alive\_pre)

life\_support\_mask \= alive\_pre | neighbor\_alive\_pre

\# \=== Вычисление дельты \===

\# Дельта вычисляется из текущего state, включая старый стресс-канал как вход.

delta \= compute\_delta(state)

\# \=== Системное обновление стресса \===

with torch.no\_grad():

    stress\_active \= STRESS\_ENABLED and not STRESS\_ABLATION\_MODE

    if not stress\_active:

        stress \= torch.zeros\_like(

            state\[:, STRESS\_CHANNEL:STRESS\_CHANNEL+1, :, :\]

        )

    else:

        \# 1\. Дельта для стресса: канал 15 исключён, мёртвые исключены.

        delta\_masked \= delta \* life\_support\_mask.float()

        delta\_for\_stress \= delta\_masked.clone()

        delta\_for\_stress\[:, STRESS\_CHANNEL, :, :\] \= 0.0

        delta\_norm \= delta\_for\_stress.abs().mean(dim=1, keepdim=True)

        \# 2\. EMA девиации.

        stress\_ema \= (

            STRESS\_EMA\_ALPHA \* stress\_ema

            \+ (1 \- STRESS\_EMA\_ALPHA) \* delta\_norm.mean()

        )

        \# 3\. Источник стресса.

        if STRESS\_TARGET\_ERROR\_MODE:

            stress\_source \= compute\_local\_target\_error(

                state=state,

                target=target,

                life\_support\_mask=life\_support\_mask

            )

        else:

            stress\_source \= clamp(delta\_norm \- stress\_ema, 0.0, STRESS\_MAX)

        \# 3b. Опциональная компрессия (Rev.7).

        if STRESS\_COMPRESS\_INPUT:

            stress\_source \= torch.log1p(stress\_source)

            stress\_source \= clamp(stress\_source, 0.0, STRESS\_MAX)

        \# 4\. Опциональное разрушение пространственной информации.

        if STRESS\_SHUFFLE\_MODE:

            stress\_source \= spatial\_shuffle(stress\_source)

        \# 5\. Обновление стресса.

        stress \= state\[:, STRESS\_CHANNEL:STRESS\_CHANNEL+1, :, :\]

        stress \= stress \* (1 \- STRESS\_DECAY)

        stress \= stress \+ STRESS\_INPUT\_GAIN \* stress\_source

        \# 6\. Диффузия стресса с reflect-паддингом.

        stress\_padded \= F.pad(stress, (1, 1, 1, 1), mode='reflect')

        stress\_blur \= avg\_pool\_or\_conv(stress\_padded)

        stress \= stress \+ STRESS\_DIFFUSION \* (stress\_blur \- stress)

        \# 7\. Ограничения и мёртвые клетки.

        stress \= clamp(stress, 0.0, STRESS\_MAX)

        stress \= stress \* life\_support\_mask.float()

\# \=== Влияние стресса на динамику \===

if STRESS\_AFFECTS\_DT and STRESS\_ENABLED and not STRESS\_ABLATION\_MODE:

    stress\_norm \= stress / STRESS\_MAX

    local\_dt \= DT \* (1.0 \+ STRESS\_TEMP\_SCALE \* stress\_norm)

    local\_dt \= clamp(local\_dt, DT, DT\_MAX\_EFFECTIVE)

else:

    local\_dt \= DT

\# \=== Применение alive-маски к delta \===

delta \= delta \* life\_support\_mask.float()

\# \=== Обновление состояния \===

new\_state \= state \+ local\_dt \* delta

new\_state\[:, STRESS\_CHANNEL:STRESS\_CHANNEL+1, :, :\] \= stress

new\_state \= clamp\_state(new\_state, STATE\_CLAMP\_MIN, STATE\_CLAMP\_MAX)

Критические требования:

- life\_support\_mask вычисляется всегда, независимо от STRESS\_ABLATION\_MODE;  
- при STRESS\_ABLATION\_MODE=True стресс остаётся нулевым;  
- при STRESS\_ENABLED=False стресс также остаётся нулевым;  
- канал 15 не управляется сетью напрямую;  
- delta маскируется до обновления состояния.

#### 12.3.7. Подсчёт дырок: border-aware версия

def count\_holes(binary\_mask):

    """

    Подсчёт дырок через компоненты фона с 4-связностью.

    Border-aware: вычитаем все компоненты фона, касающиеся границы.

    """

    background \= 1 \- binary\_mask

    labeled\_bg, num\_bg \= label(background, structure=STRUCTURE\_4)

    if num\_bg \== 0:

        return 0

    border\_labels \= set()

    border\_labels.update(labeled\_bg\[0, :\].tolist())

    border\_labels.update(labeled\_bg\[-1, :\].tolist())

    border\_labels.update(labeled\_bg\[:, 0\].tolist())

    border\_labels.update(labeled\_bg\[:, \-1\].tolist())

    border\_labels.discard(0)

    holes \= num\_bg \- len(border\_labels)

    return max(holes, 0\)

⚠️ Почему не num\_bg \- 1: если объект касается границы и разрезает фон на несколько несвязных частей, num\_bg \- 1 даст ложные дырки.

- использовать 4-связность для разметки компонент переднего плана;

#### 12.7.6. Показатель Ляпунова для E01

def compute\_lyapunov\_exponent(model, state, steps=100, eps=1e-3):

    """

    Нормированный показатель Ляпунова.

    \- Считается только по живым клеткам.

    \- Канал 15 исключён из расхождения.

    \- Канал 15 исключён из clamp\_fraction.

    \- Шаги с насыщением клампинга пропускаются.

    \- При слишком малом расхождении шаг пропускается,

      возмущение переинициализируется.

    """

    model.eval()

    perturbation \= torch.randn\_like(state) \* eps

    state\_b \= state \+ perturbation

    lyap\_sum \= 0.0

    valid\_steps \= 0

    with torch.no\_grad():

        for t in range(steps):

            state \= model(state)

            state\_b \= model(state\_b)

            alive \= (

                torch.sigmoid(state\[:, ALIVE\_CHANNEL, :, :\]) \> ALIVE\_THRESHOLD

            ).float().unsqueeze(1)

            clamp\_mask \= (state.abs() \> STATE\_CLAMP\_MAX \- 0.01)

            clamp\_mask\[:, STRESS\_CHANNEL, :, :\] \= False

            clamp\_fraction \= clamp\_mask.float().mean().item()

            if clamp\_fraction \> 0.05:

                continue

            diff \= (state \- state\_b).abs()

            diff\[:, STRESS\_CHANNEL, :, :\] \= 0.0

            diff \= diff \* alive

            d \= diff.mean().item()

            if d \< LYAPUNOV\_MIN\_DIST:

                state\_b \= state \+ torch.randn\_like(state) \* eps

                continue

            lyap\_sum \+= np.log(d / eps)

            valid\_steps \+= 1

            state\_b \= state \+ (state\_b \- state) / d \* eps

    if valid\_steps \== 0:

        return 0.0

    lyapunov \= lyap\_sum / valid\_steps

    return lyapunov

⚠️ **Rev.7:** логировать число пропущенных шагов (steps \- valid\_steps), чтобы оценка не смещалась. Если пропущено более 50% шагов, результат считается ненадёжным и логируется как предупреждение.

Интерпретация:

- λ ≈ 0 — система в критическом режиме;  
- λ \< 0 — затухает;  
- λ \> 0 — взрыв, хаос, нестабильность.

## 13\. ПОЛИТИКА ОТКАТА

### 13.1. Абсолютные пороги отката

Откат выполняется, если после проверки:

mse\_after \> mse\_before \+ 0.05

или

abs(b0\_after \- target\_b0) \> abs(b0\_before \- target\_b0) \+ 2

### 13.2. Grace window

Для немедленных откатов оставляем только катастрофические случаи:

- NaN;  
- взрыв состояния;  
- полная гибель живого паттерна;  
- критическое превышение STATE\_CLAMP\_MAX по большой доле клеток.

Для обычных действий:

- откат оценивается не мгновенно, а после GRACE\_WINDOW шагов;  
- GRACE\_WINDOW не должен ломать расписание отчётов.

Рекомендуется:

GRACE\_WINDOW \= 30

Если report\_interval \< GRACE\_WINDOW, то GRACE\_WINDOW следует уменьшить до report\_interval \- 1.

### 13.3. К каким действиям применяется откат

Откат применяется к:

- MODIFY\_DT — всегда;  
- MODIFY\_LR — только в фазе обучения;  
- MODIFY\_L1\_REG — только в фазе обучения.

Не применяется к:

- MODIFY\_LR в фазе инференса;  
- MODIFY\_L1\_REG в фазе инференса;  
- MODIFY\_TARGET\_B0;  
- APPLY\_INJURY;  
- INJECT\_MORPHOGEN;  
- CONTINUE\_TRAINING;  
- STOP.

### 13.4. Что именно откатывается

Откатываются только значения параметров:

config.DT

model.dt

В фазе обучения дополнительно:

config.LEARNING\_RATE \-\> optimizer.param\_groups

config.L1\_REG\_WEIGHT

Веса модели в фазе без обучения не откатываются.

⚠️ **Детализация для MODIFY\_DT (Rev.7):**

При применении MODIFY\_DT сохраняется rollback\_state (см. 8.2). По истечении GRACE\_WINDOW шагов сравниваются метрики. Если условие отката выполнено:

config.DT \= rollback\_state\["config\_dt"\]

model.dt \= rollback\_state\["model\_dt"\]

Если GRACE\_WINDOW пересекает границу отчёта, откат выполняется на ближайшем отчёте после завершения GRACE\_WINDOW.

### 13.5. Состояние при морфогенетических вмешательствах

Для APPLY\_INJURY и INJECT\_MORPHOGEN откат параметров не выполняется.

Однако когнитивный цикл может:

- сохранять снимок состояния до действия;  
- фиксировать ухудшение метрик;  
- записывать результат как неудачную гипотезу;  
- при катастрофическом ухудшении восстановить снимок состояния, если это явно разрешено фазой.

По умолчанию такие вмешательства считаются экспериментальными и не откатываются автоматически.

### 14.1. E01 — Criticality Primordial

Цель: проверить, что система находится в управляемом режиме, близком к критичности.

Критерий успеха:

CRITICALITY\_LYAPUNOV\_MIN \< lambda \< CRITICALITY\_LYAPUNOV\_MAX

то есть:

\-0.01 \< lambda \< 0.01

Дополнительно:

0.01 \< density\_variance \<= 10

и:

- система не умирает мгновенно;  
- система не взрывается в шум;  
- стресс не насыщается постоянно до максимума: saturation\_fraction \< 0.5.

Методология:

1. Создать одно начальное состояние.  
2. Создать его копию.  
3. Внести в копию малое возмущение порядка 1e-3.  
4. Прогнать обе траектории одинаковое число шагов.  
5. Вычислить скорость экспоненциального расхождения.  
6. Ренормализовать возмущение на каждом шаге.  
7. Расхождение считается только по живым клеткам.  
8. Канал 15 исключён.  
9. Шаги с насыщением клампинга пропускаются.  
10. При d \< LYAPUNOV\_MIN\_DIST шаг пропускается, возмущение переинициализируется.  
11. **Логировать число пропущенных шагов. Если \> 50% — результат ненадёжен (Rev.7).**

Опциональный скан критичности:

Если включён CRITICALITY\_SCAN\_ENABLED:

- просканировать не более CRITICALITY\_MAX\_CONFIGS комбинаций DT и шума;  
- каждая не более CRITICALITY\_STEPS шагов;  
- выбрать рабочую точку с λ ближайшим к 0;  
- сохранить результат в memory/criticality.json.

Если провал:

- изменить gain инициализации;  
- проверить шум;  
- проверить нулевую инициализацию последнего слоя;  
- уменьшить/увеличить DT.

### 14.5. E05 — Aging and Rejuvenation

Цель: проверить робастность аттрактора к накоплению шума и попытаться восстановить морфостаз.

⚠️ Концептуальная оговорка: шум в состояниях при фиксированных весах — это тест робастности аттрактора к постоянному внешнему шуму, а не «старение как потеря целеполагания» в полном смысле Левина.

⚠️ Накопление шума: если шум добавляется каждый шаг, за 1000 шагов даже std=0.01 даёт заметный random walk:

σ\_total ≈ 0.01 × sqrt(1000) ≈ 0.316

Пороги деградации должны быть откалиброваны с учётом этого.

⚠️ **Обязательный пилот перед основным прогоном (без пилота E05 не запускать):**

1. Запустить короткие пробы для каждого AGING\_NOISE\_STD.  
2. Измерить дрейф метрик без вмешательства.  
3. Убедиться, что деградация происходит из\-за потери устойчивости аттрактора, а не из\-за банального накопления шума.  
4. При необходимости скорректировать пороги и зафиксировать их в memory/hypotheses.md.

Протокол:

1. Взять обученную модель из E02 или E04.  
2. Отключить обучение.  
3. Запустить AGING\_STEPS шагов в eval() с малым шумом в скрытых каналах.  
4. Sweep по AGING\_NOISE\_STD: {0.01, 0.05, 0.1} — обязательный.  
5. Измерять:  
   - β₀;  
   - β₁;  
   - χ;  
   - spatial\_entropy;  
   - density;  
   - domain\_wall\_energy;  
   - symmetric\_chamfer\_error.

Пре-регистрированные пороги деградации:

AGING\_DEGRADATION\_THRESHOLD\_B0 \= 2

AGING\_DEGRADATION\_THRESHOLD\_ENTROPY \= 0.15

Пре-регистрированный порог восстановления:

AGING\_RECOVERY\_THRESHOLD \= 0.8

Критерий успеха:

- при AGING\_NOISE\_STD \= 0.01: система не должна деградировать;  
- при AGING\_NOISE\_STD \= 0.1: система должна деградировать;  
- при хотя бы одном уровне шума: деградация зафиксирована и предпринята попытка восстановления.

Если ни при одном уровне шума деградация не происходит — эксперимент не доказывает ничего и должен быть повторен с большим шумом или другим протоколом.

Если метрики деградируют, агент может попытаться:

- мягкий INJECT\_MORPHOGEN;  
- MODIFY\_DT;  
- CONTINUE\_TRAINING.

Обязательно:

- записать кривую старения для каждого уровня шума;  
- записать момент деградации;  
- записать применённые вмешательства;  
- записать эффект омоложения.

1. **Агент с экономикой** (RuleBasedAgentV2 с АТР-бюджетом и кулдаунами).  
2. **Реактивный агент без экономики** (тот же RuleBasedAgentV2, но без ограничений бюджета и кулдаунов — может спамить действиями).  
3. **Случайная политика** (случайный выбор действия из допустимых, с теми же ограничениями бюджета для честного сравнения).

Метрики сравнения:

- итоговое улучшение целевой метрики;  
- число вмешательств;  
- число катастрофических ухудшений;  
- время до стабилизации.

Если агент с экономикой не лучше реактивного агента или случайной политики — это фиксируется как результат.

Критерий успеха:

- есть улучшение метрик или более быстрое восстановление;  
- число вмешательств не растёт бесконтрольно;  
- АТР-бюджет не нарушается;  
- кулдаун травмы соблюдается;  
- кулдаун морфогена соблюдается;  
- нет катастрофических ухудшений из\-за спама действиями.

Разрешённые действия:

- CONTINUE\_TRAINING  
- MODIFY\_DT  
- APPLY\_INJURY  
- INJECT\_MORPHOGEN

Приоритет:

1. Наблюдение.  
2. Мягкое морфогенетическое вмешательство.  
3. Травма только если нужно проверить регенерацию.  
4. Глобальные гиперпараметры только если морфогенетические сигналы не дают эффекта.

### 14.8. E08 — Self Theory

Цель: агент формулирует предсказательные теории.

Критерий успеха: теория сохраняет предсказательную силу.

Примеры теорий:

- если β₀ слишком высок, уменьшить DT;  
- если регенерация медленная, ввести морфоген в канал 5 у границы раны;  
- если стресс растёт, а плотность падает, уменьшить DT;  
- если система стабильна, не вмешиваться;  
- если symmetric\_chamfer\_error высок при верном β₀, возможна геометрическая галлюцинация.

### 14.9. E09 — Full Autonomous Loop

Цель: полный автономный цикл.

Критерий успеха:

- цель достигается за разумное число шагов;  
- регенерация происходит без ручного микроменеджмента;  
- отчёты идут строго по расписанию;  
- память накапливается;  
- нет облачных API;  
- нет блокирующего input();  
- АТР-бюджет вмешательств соблюдается;  
- кулдаун травмы соблюдается;  
- система не самовоскрешается из мёртвого поля.

⚠️ На ноутбуке с 8 ГБ VRAM E06–E09 должны выполняться в минимальной конфигурации и только после успешного завершения слоёв 1 и 2\.

Перед запуском экспериментов в memory/hypotheses.md фиксируются числовые фальсифицируемые гипотезы.

Пример:

\#\# H1: Стресс-шеринг ускоряет регенерацию

При стресс-канале (STRESS\_ENABLED=True) медианный recovery\_steps

снижается на ≥20% против базлайна (STRESS\_ENABLED=False, канал 15 \= нули)

на ≥6 сидах, при прочих равных условиях.

Проверка: парный тест Уилкоксона, p \< 0.05.

Нулевая гипотеза: различие отсутствует.

\#\# H2: Стресс не вызывает насыщения

При стандартном обучении доля шагов, на которых

средний стресс \> 0.9 \* STRESS\_MAX (saturation\_fraction), не превышает 5%.

\#\# H3: Морфоген снижает число глобальных вмешательств

При активном использовании INJECT\_MORPHOGEN число MODIFY\_DT

за полный цикл E07 не превышает 3\.

\#\# H4 (опционально): Пространственная информация стресса полезна

Стресс-канал в обычном режиме даёт меньший медианный recovery\_steps,

чем STRESS\_SHUFFLE\_MODE=True, на ≥6 сидах.

Проверка: парный тест Уилкоксона, p \< 0.05.

\#\# H5 (Rev.7): Экономика вмешательств снижает число действий

Агент с экономикой выполняет не более 50% вмешательств

по сравнению с реактивным агентом без экономики при сопоставимом

улучшении целевой метрики в E07.

\#\# H6 (Rev.7): Статическая ошибка невидима стрессу

Если система стабильно находится в неверной конфигурации

(высокий symmetric\_chamfer\_error, низкий stress\_mean),

стресс-канал не инициирует коррекцию без внешнего вмешательства агента.

Без пре-регистрации эксперимент рискует стать «запустили и понравилось».

⚠️ **Защита от p-hacking (Rev.7):** для каждого эксперимента заранее фиксируется один **primary endpoint**. Все остальные метрики — secondary и не используются для принятия решения об успехе/провале гипотезы. Если необходимо тестировать несколько первичных метрик, применяется поправка на множественные сравнения (Бонферрони или Holm).

## 16\. КОГНИТИВНЫЙ КОНТУР

### 16.1. Принцип работы

Цикл:

1. Наблюдение  
2. Рассуждение  
3. Действие  
4. Проверка результата  
5. Отчёт  
6. Память

### 16.2. Ограничения

- только локальные вычисления;  
- никаких внешних облачных API;  
- только валидный JSON от агента;  
- каждое решение пишется в decisions\_log.jsonl;  
- отчёт строго каждые report\_interval шагов;  
- при неуверенности агент выбирает CONTINUE\_TRAINING;  
- топология только на CPU;  
- симуляция на GPU, если доступен;  
- агент на CPU.

### 16.3. Автономный агент

Вместо блокирующего input() нужно использовать интерфейс агентского бэкенда.

Допустимые реализации:

- RuleBasedAgent — детерминированная эвристика;  
- RuleBasedAgentV2 — основной рекомендуемый контур;  
- HumanConsoleAgent — ручной ввод, только явно;  
- LocalLLMAgent — локальная LLM на CPU, если ресурсы позволяют.

Если бэкенд не указан, по умолчанию должен использоваться RuleBasedAgent или RuleBasedAgentV2.

⚠️ **Rev.7:** RuleBasedAgentV2 является несущей конструкцией. Локальная LLM подключается **только после** завершения слоёв 1 и 2 MVP. Если LLM тормозит или даёт невалидный JSON, всё падает в RuleBasedAgentV2.

### 16.4. RuleBasedAgentV2

Рекомендуется реализовать агента как машину состояний.

RuleBasedAgentV2 является несущей конструкцией системы.

Локальная LLM может использоваться только для:

- нарратива;  
- генерации гипотез;  
- интерпретации JSON-логов;  
- пояснений в отчётах.

Локальная LLM не должна:

- рассчитывать normalized\_dose;  
- вычитать стоимость из АТР-бюджета;  
- проверять кулдауны;  
- выбирать окончательные числовые параметры INJECT\_MORPHOGEN;  
- подменять action\_validator.

Если JSON от LLM не проходит валидацию, bridge.py должен отбросить его и передать управление эвристикам.

#### 16.4.1. Состояния системы

- UNKNOWN  
- STABLE\_HEALTHY  
- STABLE\_OFF\_TARGET  
- REGRESSING  
- INJURED  
- COLLAPSING  
- EXPLODING  
- CRITICAL\_UNSTABLE

#### 16.4.2. Таблица политик

| Состояние | Действие |
| :---- | :---- |
| STABLE\_HEALTHY | CONTINUE\_TRAINING или STOP, если фаза завершена |
| STABLE\_OFF\_TARGET | мягкий INJECT\_MORPHOGEN |
| REGRESSING | уменьшить DT или CONTINUE\_TRAINING |
| INJURED | морфоген у границы раны |
| COLLAPSING | уменьшить DT, остановить травму, сохранить память |
| EXPLODING | уменьшить DT, усилить регуляризацию, STOP при необходимости |
| CRITICAL\_UNSTABLE | только наблюдение или минимальный морфоген |

#### 16.4.3. Нюансы состояний

Для различения «медленно регрессирует» и «быстро коллапсирует»:

if b0\_error\_rate \> 0.5 per 10 steps:

    state \= COLLAPSING

elif b0\_error\_rate \> 0.1 per 10 steps:

    state \= REGRESSING

#### 16.4.4. Учёт производной стресса

Агент при принятии решения учитывает stress\_derivative:

if stress\_mean \> 0.5 \* STRESS\_MAX and stress\_derivative \< 0:

    action \= "CONTINUE\_TRAINING"

#### 16.4.5. Правило «Ленивый Агент» в RuleBasedAgentV2

⚠️ **Rev.7:** жёсткое правило (см. 8.14):

if (symmetric\_chamfer\_error \> SYMMETRIC\_CHAMFER\_HALLUCINATION\_THRESHOLD

        and stress\_mean \< 0.2 \* STRESS\_MAX):

    \# Статическая геометрическая ошибка, стресс слеп

    \# Агент ОБЯЗАН вмешаться через морфоген или диагностику

    action \= "INJECT\_MORPHOGEN"  \# в зону максимального локального расхождения

    \# ИЛИ: временно включить STRESS\_TARGET\_ERROR\_MODE для диагностики

Это правило не может быть переопределено другими эвристиками, если бюджет и кулдауны позволяют.

## 20\. КРИТЕРИИ УСПЕХА ФИНАЛЬНОЙ СИСТЕМЫ

Финальная система считается успешной, если она:

- самоорганизуется из шума в целевую топологию;  
- регенерирует после повреждений;  
- адаптируется к изменению цели;  
- описывает себя через языковую или эвристическую агентскую модель;  
- принимает решения о модификации параметров;  
- формирует теорию о своём поведении;  
- обладает элементами целеполагания;  
- генерирует регулярные отчёты без поломки расписания;  
- не использует внешние облачные API;  
- работает в пределах 8 ГБ VRAM;  
- не самовоскрешается из мёртвого поля;  
- имеет согласованную топологию между симуляцией и мониторингом;  
- способна использовать морфогенетические сигналы вместо прямого внешнего принуждения;  
- демонстрирует управляемый стресс-шеринг;  
- демонстрирует морфостаз или восстанавливается после старения;  
- соблюдает экономику вмешательств;  
- демонстрирует измеримое преимущество стресс-канала над нулевым базлайном;  
- если выполнена абляция STRESS\_SHUFFLE\_MODE, демонстрирует преимущество пространственного стресса над перемешанным для сильного утверждения о пространственной информации;  
- **демонстрирует преимущество агента с экономикой над реактивным агентом без экономики в E07 (Rev.7);**  
- **все стохастические операции детерминированы и воспроизводимы при фиксированном сиде (Rev.7).**

## 21\. ТЕОРЕТИЧЕСКИЕ ОГРАНИЧЕНИЯ И БУДУЩИЕ УЛУЧШЕНИЯ

### 21.1. BPTT против локальности

Текущее обучение использует truncated BPTT. Это практический компромисс.

Однако концептуально BPTT является глобальным алгоритмом и может противоречить принципу чисто локальной самоорганизации.

В будущих версиях рекомендуется рассмотреть:

- Equilibrium Propagation;  
- Contrastive Hebbian Learning;  
- локальные энергетические методы.

Важно: не называть текущее обучение «локальным». Это BPTT.

### 21.2. Топология только мониторится

Текущая версия не гарантирует топологический результат.

В будущих версиях можно исследовать:

- дифференцируемые аппроксимации β₀ и β₁;  
- soft topological losses;  
- персистентные гомологии с дифференцируемыми приближениями;  
- регуляризаторы связности и полостей.

### 21.3. Автономность когнитивного контура

Текущая версия должна поддерживать:

- RuleBasedAgent как безопасный минимум;  
- RuleBasedAgentV2 как основной контур;  
- локальную LLM на CPU как опцию.

Запрещено:

- использовать облачные LLM API;  
- блокировать цикл на ручном вводе без явного режима;  
- запускать LLM на GPU одновременно с NCA;  
- доверять LLM расчёт бюджета и параметров вмешательства.

### 21.4. Иерархическая память и многоуровневая топология

Устойчивая самоорганизация требует не только локальности, но и иерархии.

В будущих версиях нужно рассмотреть:

- многоуровневые скрытые поля;  
- медленные макроклеточные каналы;  
- локальные клики или модули;  
- разделение быстрых и медленных процессов памяти;  
- top-down морфогенетические сигналы без глобального градиента.

### 21.5. Геометрия против топологии

Важно не путать:

- геометрическая цель: маска пикселей;  
- топологическая цель: инвариант формы.

В текущей версии система работает преимущественно с геометрической целью. Это допустимо как базовый этап, но не является финальной проверкой гипотез Левина.

### 21.6. Стресс как прокси

Стресс-канал — это упрощённый прокси-механизм.

Он не является полноценной симуляцией:

- ионных каналов;  
- мембранных потенциалов;  
- электрофизиологии ткани.

Это именно информационный сигнал координации.

### 21.7. Слепота стресса к статическим ошибкам

Стресс в текущей версии считается из девиации изменений состояния. Поэтому он может быть низким, если система стабильно находится в неверной конфигурации.

Это означает:

- стресс не заменяет метрики цели;  
- агент обязан использовать symmetric\_chamfer\_error, β₀, β₁;  
- для статических ошибок нужен морфоген или изменение динамики, а не только ожидание реакции стресса;  
- **правило «Ленивый Агент» (8.14) обязательно к исполнению (Rev.7).**

### 21.8. Статистическая мощность абляций

Текущий протокол абляции:

- минимум 6 сидов;  
- рекомендуется 10;  
- парный тест Уилкоксона.

Для публикационного уровня рекомендуется:

- 10–15 сидов;  
- отчётность с доверительными интервалами;  
- **обязательный effect size (Rev.7);**  
- **обязательный bootstrap CI для медианной разницы (Rev.7);**  
- **пре-регистрация primary endpoint до запуска (Rev.7);**  
- **поправка на множественные сравнения при тестировании нескольких метрик (Rev.7).**

### 21.9. Ограничения E05

Шум в состояниях при фиксированных весах — это тест робастности аттрактора, а не полноценное биологическое старение.

Полноценное моделирование старения требует:

- деградации весов;  
- потери цели;  
- накопления ошибок в скрытых представлениях.

Это отложено до будущих версий.

### 21.10. Цитирование

Все ссылки на работы Левина и соавторов должны быть верифицированы перед включением в публикации. Если источник не может быть найден онлайн, это явно указывается в memory/discoveries.md.

### 21.11. Gameable stress signal

⚠️ **(Rev.7)** Стресс-вход считается из |delta| самой модели. Теоретически сеть может научиться:

- генерировать девиации для повышения стресса и получения большего local\_dt;  
- маскировать девиации для снижения стресса.

Контроль STRESS\_SHUFFLE\_MODE частично ловит первый случай, но не исключает его полностью. Данное ограничение должно быть зафиксировано в отчётах. В будущих версиях можно рассмотреть стресс на основе внешнего сигнала (например, целевой ошибки), а не собственной динамики модели.

Ты — автономный исследователь проекта MORPHOGENESIS версии v5.5-EXP FINAL, ревизия Rev.7.

python smoke\_test.py

## 25\. ИТОГОВОЕ ЗАМЕЧАНИЕ

Эта спецификация устраняет следующие критические проблемы прошлых версий и ревизий:

- «воскрешение мёртвых» через неправильный ALIVE\_THRESHOLD;  
- самовоскрешение после обучения через пост-апдейтную alive-маску;  
- поломку расписания отчётов из\-за CONTINUE\_TRAINING;  
- неоднородную динамику из\-за отсутствия сброса пула после warmup;  
- отсутствие явного включения маски в оценке;  
- расхождение связности между topology.py и bridge.py;  
- расхождение между тороидальной физикой и плоской топологической разметкой;  
- неавтономность когнитивного контура;  
- небезопасные пути и версионную рассинхронизацию;  
- ложную метрику чувствительности в E01;  
- отсутствие у агента мягкого морфогенетического действия;  
- отсутствие экономики вмешательств;  
- отсутствие системного стресс-канала;  
- отсутствие измерения старения и морфостаза;  
- отсутствие стигмергической памяти агента;  
- несходящуюся арифметику бюджета вмешательств;  
- неправильную связность для дырок;  
- потерю alive-маски в псевдокоде;  
- петлю положительной обратной связи стресс→DT→стресс;  
- ловушку смертельного replace\_all\_fresh();  
- неопределённость бинаризации для топологии;  
- фиктивный откат для LR/L1 в фазе инференса;  
- тавтологичный тест мёртвого поля на необученной модели;  
- нефальсифицируемость E05;  
- отсутствие абляции стресс-канала;  
- отсутствие гистерезиса для topological\_hallucination;  
- стоки стресса на границах;  
- рассинхронизацию пула;  
- отсутствие супервизии альфа-канала;  
- отсутствие пре-регистрации гипотез.
