# X123 — the identity rule, confirmed in the code and pinned by a gate: a uid's life is one generation

**Plan:** none — this is a code-and-data check, registered in the queue as X123 (tooling, no GPU). It is reported rather than pre-registered because it changes
no data, only what the line may call its numbers.

## The rule, read from the implementation

`scripts/field_track.py` assigns identity to each surviving component: it inherits the uid of the best-overlapping previous component, **unless** the component is
a split daughter and `--split-new-uid` is on, in which case it gets a fresh uid. At a split, *every* daughter whose best overlap is the parent is a split child, so
**no daughter inherits the mother's uid** — the mother's identity ends.

That is what the code does, and the comment next to it says why: a daughter needs its own identity or its peak is inseparable from the mother's, and "size
inheritance" cannot be measured. The retirement of the mother is a consequence of that choice, not a separate decision — and it is now the line's official reading
of what a uid means.

## The rule, checked on the data

`scripts/check_uid_rule.py` reads stored runs and asserts that no parent's last logged appearance comes after its child's first appearance:

```
[uid-rule] runs: 20, pairs checked: 4162
[uid-rule] OK — no parent outlives its child's birth
```

4 162 genealogical pairs across the twenty dense runs, zero violations. The check is now a gate in `make verify` (1.7 s), because a run that violated it would
silently invalidate every survival number in the line — and because a rule that lives only in a comment is a rule nobody enforces.

## What this means for the line's vocabulary

A uid's lifetime is **time from birth to its first division** — that is, a **generation time**, not a persistence time. Every number the line has called
"lifetime" is therefore a generation time:

| where | what it measures | correct name |
|---|---|---|
| X88/X89 half-life of size correlations | decay per generation | generation-indexed memory (name stands) |
| X92 "area vs lifetime" | area vs time to division | area vs **generation time** |
| X93/X97 sisters' lifetimes | sisters' generation times | **generation times** |
| X113/X114 depth and rate | generations reached per unit time | stands, and is the same quantity as the others |

The earlier findings do not change — the numbers are the same — but the words do, and a reader of the manuscript must not think "lifetime" means persistence. The
three survival readouts from X122 remain the only ones that speak about persistence, and only the subtree ones do it correctly.

## What this closes

- X122's withdrawal is explained by the code, not only by the data: the negative "cost of division" coefficient is the identity rule.
- The queue's X123 is closed: the rule is intended, documented here, and enforced by a gate.
- X121's failure has the same root, so X122's plan to rebuild the hazard model is **cancelled rather than fixed**: a hazard model on uid presence would model
  "did not divide", which is not a hazard of death.

## Caveats

- The check covers the twenty x108 runs (they carry `split_new_uid`); runs without the flag are skipped by design, and the script reports which runs it read.
- If a future series uses a different `--overlap`, a mother may have several children with the same best parent; the check still holds because every such child
  gets a new uid.
- The word "lifetime" appears in many older reports; they are history and are not rewritten, but the plan section states the reading once, where a new reader will
  look.
