# H-ALIVE-36 / W2-bud-d2: несколько почек на компоненту — пре-регистрация

- **Дата:** 2026-10-25
- **Статус:** пре-регистрация на ревью. Запуск — **после** финиша V1b и приёмки его чисел.
- **ПЕРВАЯ СТРОКА: это ТРЕТЬЯ смена единицы размножения.** Мир `W2-bud-d2`, не `W1` и не
  `W2-bud`: числа **не сопоставимы** ни с V8/§10ae, основанием/§10af, дозой/§10ac,
  `merge=keep`/§10ai, E/§10ag, ни с §10ao/§10ap/§10aq/§10as. Сравнение — только «в W2-bud было так,
  в W2-bud-d2 стало так», без арифметики «во сколько раз».

## Что именно меняется (и почему не «два потомка на клетку»)

Проверено по коду: `spore_cells = 2` по умолчанию — **каждое почкование уже даёт две клетки**
(`Pond.bud`: `take = min(spore_cells, свободных)`). Поэтому «два потомка на клетку» в буквальном
смысле — no-op. Настоящий ограничитель другой:

`find_buds()` возвращает **одну маску на компоненту** (колонию), а `budding_parent` выбирает в ней
**одну клетку**. Значит **на колонию в 500 клеток приходится один бутон за шаг** (2 клетки), и
линия-мутант получает бутон только если именно её клетка выбрана по `score`. Отсюда медиана 4 линии
с данными (§10ao.1, §10as).

**Изменение:** новый флаг `--buds-per-component N` (по умолчанию 1 = поведение `W2-bud`): при
`N > 1` `budding_parent` возвращает до `N` **разных клеток** компоненты (топ по тому же `score`),
и каждая даёт свой бутон (2 клетки). Это не новая физика роста, а снятие искусственного «одного
бутона на колонию».

## Якорь (обязателен до серии)

`--budding-unit colony` (при любом `--buds-per-component`) обязан остаться **бит-в-бит** с V8:
`into_resident/majority seed1` = **66679 / 1.0 / 0.0111 / 449 / 5 / 0.95065 / 10.0 / 936 / 459**.
Если разошёлся — это сломанный старый мир, серия не запускается.

## Арифметика до данных (§3c) — размер линий и df

**Что задаёт размер линии.** Линия растёт только собственными бутонами: `+2` клетки за бутон
(`spore_cells = 2`). Чтобы линия попала в «данные», нужно `cells ≥ 5`, то есть **≥ 3 бутона**
(2 → 4 → 6).

**Сейчас (N = 1):** на колонию один бутон за шаг, и его получает самая «богатая» клетка; линия-мутант
с 2–4 клетками почти никогда не выигрывает `score` у предковой. Отсюда медиана 4 линии с данными
(§10as) и медиана размера линии **1** клетка (§10ao.1).

**Ожидание при N = 3:** каждая из трёх самых богатых клеток колонии даёт бутон. Если линия-мутант
имеет 2–4 клетки, её шанс попасть в топ-3 существенно выше, чем в топ-1. Ожидаемый эффект:
число линий с данными **медиана 6–9** (против 4), размер линии растёт ~в 2–3 раза быстрее.
**Цель — медиана ≥ 7 линий с данными**, тогда `df = n − 3 ≥ 4` для частной корреляции с двумя
предикторами, и вердикт выносим, а не «направление».

**Риск, названный ведущим, и как он проверяется.** Если три «богатейшие» клетки компоненты — почти
всегда клетки предка (у него и масса, и лучший `score`), то `N = 3` даст предку три бутона вместо
одного, и **доля топ-1 линии вырастет**, а линии мутантов станут не длиннее, а короче — тот же
искусственный ограничитель, только усиленный. Поэтому пилот считает **три** числа, а не одно:

| # | величина | определение | ожидание |
|---|---|---|---|
| 1 | медиана линий с данными | `#{t : type_counts[t] ≥ 5 и lineage_spores[t] ≥ 1}` | 6–9 |
| 2 | **доля топ-1 линии по клеткам** | `max_t type_counts[t] / Σ_t type_counts[t]` | **не должна вырасти** относительно N = 1 (в `W2-bud` медиана 0.856, §10ao.1) |
| 3 | **линий, получивших ≥ 1 бутон** | `#{t : lineage_spores[t] ≥ 1}` | больше, чем при N = 1 |

Числа 1 и 3 считаются из существующих полей артефакта (`type_counts`, `lineage_spores`), нового
логгера не требуют; оговорка: частичный бутон (один свободный сосед) даёт 1 спору, поэтому
`lineage_spores ≥ 1` — верхняя граница числа «получивших бутон».

**Порог решения (пилот 2 сида, ДО серии):**
- **медиана линий ≥ 7 И доля топ-1 не выросла** (≤ 0.856 + 0.02) → серия идёт, вердикт по
  коэффициенту (`df ≥ 4`);
- **линии не выросли (< 7) ИЛИ доля топ-1 выросла** → **серию не гнать**, а перейти на другую ручку:
  `--buds-per-component 3 --one-bud-per-lineage` (не больше одного бутона на линию в компоненте) —
  это точечное снятие ограничителя, а не его усиление, и логически ближе к вопросу «может ли мутант
  размножаться внутри тела предка»;
- 5 ≤ медиана < 7 при неухудшившейся топ-1 → серия с оговоркой «df < 4, публикуется направление».

**Якоря (два, до серии).** (1) `--budding-unit colony --buds-per-component 1` — **бит-в-бит**
66679 / 459 (старый мир не сломан); (2) `--budding-unit colony --buds-per-component 3` — **тоже
бит-в-бит**: при `budding_unit = colony` новый флаг обязан игнорироваться. Расхождение во втором
якоре означает, что флаг протекает в старую механику.

## Дизайн

| шаг | что | стоимость |
|---|---|---|
| 1 | якорь (colony, N = 3) | 2 мин |
| 2 | пилот: 2 сида × `cell` при N = 3 | 10 мин |
| 3 | решение по порогу (см. выше) | — |
| 4 | серия: 10 сидов × `cell` при выбранном N | ~50 мин |

Конфигурация — как в §10as (`eps = 4.0`, 600 шагов, `m = 0.05`, `freq_dep = 0`, `spore_bias = score`,
`type_level = cell`, `budding_unit = cell`), меняется только `--buds-per-component`.

## Критерий (до данных)

1. **Структура:** `I_obs > I_null(95 %)` в ≥ 7/10 сидов (как в §10aq; нуль-модель `i_null.py`,
   `rate = sum(spores)/sum(cells)`).
2. **Данные:** медиана линий с данными ≥ 7 (иначе «невалидна по данным», `ρ` не тянем).
3. **Цена:** медиана `ρ_partial(признак, cell_steps | energy_per_cell_time)` ≤ −0.3 **и**
   отрицательный знак в ≥ 7/10 сидов — тогда цена установлена.
4. **Выгода (третье объяснение):** медиана ≥ +0.3 и положительный знак в ≥ 7/10 — тогда признак не
   цена, а выгода.
5. **Бедность:** не критерий; публикуется `ρ(признак, energy_per_cell_time)` как описательная
   величина (после §10as «бедность не отклонена и не подтверждена»).

## Ожидание (до данных)

- Число линий с данными вырастет (медиана 6–9), `I_obs` останется выше нуля.
- `ρ(признак, cell_steps)` останется отрицательным (медиана ≈ −0.6).
- `ρ_partial` — либо устойчиво отрицательный (цена), либо нет; при `df ≥ 4` это будет **вердикт**, а
  не направление.

## Ограничения

1. `N = 3` — произвольный выбор; сетка по N не строится (это отдельный вопрос).
2. Один layout, `freq_dep = 0`, `spore_bias = score`.
3. Смена механики почкования ⇒ **нельзя** сравнивать абсолютные числа с `W2-bud`; сравниваются
   только структура (выше ли нуля), размер линий и знаки корреляций.

## Как запускается (свип)

`_hourly/run_w2budd2_sweep.ps1` — только через `pwsh -NoProfile -File`; строка `start` пишется до
первого прогона; пилот (сиды 1–2) идёт первым, и **решение по порогу принимается по нему**, а не по
серии. Якорь — отдельным прогоном до свипа.

## Стоимость

Якорь 2 мин + пилот 10 мин + серия 50 мин ≈ **1 час GPU** + правка `world/` (~20 мин).
