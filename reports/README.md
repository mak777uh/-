# Лабораторный журнал Morphogenesis

Это публичный журнал лаборатории: что проверяли, что получили, что опровергнуто и что
дальше. Репозиторий — не только код, но и протокол исследований: отчёты пишутся по
артефактам, а не по памяти, и отрицательный результат считается таким же результатом,
как положительный.

## Правила

1. Число в отчёте имеет источник: файл, поле, коммит. Если источник — лог, он указан.
2. Старые отчёты не редактируются задним числом. Уточнение оформляется отдельным
   отчётом или пометкой с датой (правило §7.7 спецификации).
3. План эксперимента фиксируется до запуска (pre-registration). После запуска гипотезы
   не переписываются под результат.
4. Отрицательный результат публикуется: он идёт в
   [`negative_results.md`](../morphogenesis/memory/negative_results.md) и в отчёт.
5. Код и машинные артефакты — в `morphogenesis/`; здесь — человекочитаемая
   интерпретация и ссылки.
6. Секреты, логи и чекпоинты в git не попадают.
7. Хороший научный результат — на любой стадии — закрывается не только отчётом:
   пишется или обновляется статья в [`../articles/`](../articles/README.md),
   строка журнала в [`../README.md`](../README.md) и кусочек будущей публикации
   в [`../manuscript/`](../manuscript/README.md); явно называются следующие
   гипотезы для проверки. Отчёт без статьи, строки README и вклада в рукопись —
   это промежуточная записка, а не закрытый результат.

## Цикл работы

Работа лаборатории идёт по кругу, и отчёт — только одна его стадия:

1. **Работа с источниками в публикациях** — что уже сказано по нашему вопросу;
   след в [`../library/`](../library/README.md).
2. **Просмотр наших данных и статей** — что уже измерено у нас.
3. **Наша проверяемая гипотеза** — формулировка с критерием опровержения,
   зафиксированная до запуска.
4. **Проверка** — прогон, сырой артефакт, манифест.
5. **Отчёт и статья** — карточка эксперимента здесь, связный текст в
   [`../articles/`](../articles/README.md), следующие гипотезы — в обоих.
6. **Работа с источниками → новая гипотеза** — новый виток.

Очередь гипотез лаборатории лежит в `lab/registry.json` → `program.next_hypotheses`,
у каждого закрытого эксперимента — свой список `next_hypotheses`. Проверяет это
`python scripts/lab.py validate`. Полный контракт — в
[`../AGENTS.md`](../AGENTS.md) §3a.

## Статусы

| Статус | Значение |
| --- | --- |
| `план` | Гипотезы и протокол зафиксированы, запуска ещё не было. |
| `идёт` | Эксперимент выполняется; числа предварительные. |
| `закрыто` | Результат получен и записан; вывод не зависит от будущих прогонов. |
| `опровергнуто` | Гипотеза проверена и не подтвердилась — это результат. |
| `заблокировано` | Не хватает решения или ресурса; причина указана. |

## Машинный контур

Таблица ниже — человеческий снимок. Актуальное машинное состояние, активные
прогоны, блокеры и требования к чекпоинтам лежат в [`../lab/`](../lab/README.md):

```bash
python scripts/lab.py status     # фаза, активные прогоны, блокеры
python scripts/lab.py validate   # контракт registry/state/runs/journal
```

Порядок чтения для агентов и границы запуска — в [`../AGENTS.md`](../AGENTS.md).
Если отчёт и `lab/state.json` расходятся, прав первичный артефакт или журнал, а
отчёт помечается уточнением с датой.

## Как добавить отчёт

1. Скопировать [`TEMPLATE.md`](TEMPLATE.md) в `YYYY-MM-DD-<тема>.md`.
2. Заполнить по артефактам; каждое число — со ссылкой на источник.
3. Добавить строку в таблицу выше.
4. Обновить строку журнала экспериментов в [`../README.md`](../README.md):
   статус, вердикт, ссылки.
5. Дописать кусочек в [`../manuscript/paper.md`](../manuscript/paper.md),
   запись в [`../manuscript/CHANGELOG.md`](../manuscript/CHANGELOG.md) и строку
   карты в [`../manuscript/README.md`](../manuscript/README.md).
6. Прогнать `python scripts/lab.py validate`.
7. Коммит: `reports: <тема> (YYYY-MM-DD)`.
