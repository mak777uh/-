# Project Morphogenesis

Морфогенетическое управление нейронными клеточными автоматами (NCA) под управлением автономного когнитивного агента.

Проект реализует инженерную модель идей Майкла Левина о биологической «целенаправленности»: локальные клетки без глобального плана, стресс как сигнал рассогласования с целевой морфологией и экономия вмешательств («ленивый агент»), которая заставляет систему достигать цели минимальными действиями.

> Спецификация: **v5.6-EXP FINAL**, ревизия **Rev.11-IMPLEMENTATION-READY** (`Stress, Teleonomy Lite, Intervention Economy`).

## Идея

Нейронный клеточный автомат обучается воспроизводить целевую морфологию (например, три изолированных диска). Поверх симулятора работает **когнитивный контур**: он периодически получает метрики состояния, оценивает их и принимает решения о вмешательствах, стремясь к целевой топологии с минимальными затратами.

Система оперирует тремя научными конструктами:

- **Stress** — отдельный системный канал (15), отражающий локальное рассогласование; служит входным сигналом для агента и диагностики.
- **Teleonomy Lite** — целеполагание «снизу вверх»: цель хранится в памяти (стигмергия), а достижения добиваются локальными правилами.
- **Intervention Economy** — АТР-бюджет и стоимости действий; бесплатный `CONTINUE_TRAINING` не должен доминировать над осмысленными вмешательствами.

## Ключевые возможности

- Двухканальная NCA: видимый канал (0) + alive-маска (1) + скрытые каналы (2–14) + стресс-канал (15).
- Топологический мониторинг: β₀, β₁, χ и симметричный Chamfer — **только мониторинг**, без дифференцируемых прокси.
- Детектор галлюцинаций с гистерезисом по MSE и Chamfer.
- Когнитивный цикл «восприятие → решение → действие» с валидацией каждого действия.
- Морфогенетические вмешательства и травма с кулдаунами и бюджетом.
- Полная воспроизводимость: фиксированные сиды и детерминированные `torch.Generator`.
- Серия из семи экспериментов (E01–E07) с парными статистическими тестами.

## Архитектура

```
┌──────────────────────────────────────────────────────────┐
│  Когнитивный контур (cognition/)                          │
│  protocol → agent_backends → action_validator → bridge    │
│        ▲                                        │         │
│        │ метрики / отчёты                        │ действия │
│        │                                        ▼         │
│  Ядро NCA (nca_core.py) ── stress, alive-mask, morphogens │
└──────────────────────────────────────────────────────────┘
```

- **`nca_core.py`** — ядро автомата: perception-layer, стресс-механизм с EMA (разрыв петли «стресс → dt → стресс»), alive-маска из pre-update состояния, инъекции морфогенов.
- **`topology.py`** — топологические инварианты и симметричный Chamfer (двойственная связность: 8 для foreground, 4 для фона/дырок).
- **`cognition/`** — протокол решений, эвристический агент (`RuleBasedAgentV2`), единый валидатор действий, мост к симулятору, память и отчётность в Markdown.
- **`train.py`** — обучение с truncated BPTT, пул состояний, NaN/OOM-гарды, атомарные чекпоинты с метаданными.
- **`experiment_manager.py`** — оркестрация серии экспериментов и статистика (парный тест Уилкоксона, effect size, bootstrap CI).

### Действия агента

| Действие | Стоимость | Описание |
| --- | --- | --- |
| `CONTINUE_TRAINING` | 0.0 | Продолжить обучение без вмешательства |
| `MODIFY_DT` | 0.10 | Изменить шаг интегрирования |
| `MODIFY_LR` | 0.10 | Изменить learning rate |
| `MODIFY_L1_REG` | 0.10 | Изменить вес L1-регуляризации |
| `MODIFY_TARGET_B0` | 0.20 | Скорректировать целевую топологию |
| `INJECT_MORPHOGEN` | 0.50 | Локальная инъекция морфогена (каналы 2–14) |
| `APPLY_INJURY` | 0.0 | Травма (с глобальным кулдауном) |
| `STOP` | 0.0 | Остановить контур |

## Установка

Требуется Python 3.11+ и (для проверки детерминизма §9.2) CUDA-сборка torch.

```bash
git clone https://github.com/mak777uh/-.git morphogenesis-repo
cd morphogenesis-repo
python -m venv .venv
# CPU (тесты и диагностика):
.venv/Scripts/python.exe -m pip install -U pip
.venv/Scripts/python.exe -m pip install -r requirements.txt
# GPU RTX 3070 8GB (обучение, §9.1-9.2) — установка из КОРНЯ репозитория:
.venv/Scripts/python.exe -m pip install --index-url https://download.pytorch.org/whl/cu124 --extra-index-url https://pypi.org/simple -r requirements-cuda.txt
```

Форма `python -m pip` вместо `.venv/Scripts/pip`: первый гарантированно
обращается к интерпретатору этого venv, второй в PowerShell/Git Bash иногда
уходит в системный Python или не выводит ничего. Если после установки
`torch.cuda.is_available()` вернул `False` — значит прилетела CPU-сборка, и
§9.2 проверить нельзя.

Локальный «CI» (из корня репозитория):

```bash
python run_tests.py           # pytest + smoke_test
python run_tests.py --quick   # только pytest
```

### Проверенное окружение (слой 0 пройден)

| Компонент | Значение |
| --- | --- |
| Python | 3.13.11 (venv `.venv` в корне репозитория) |
| torch | 2.6.0+cu124, `torch.cuda.is_available() == True` |
| GPU | RTX 3070 Laptop, 8 ГБ (пик VRAM на smoke-тесте ~1 МБ) |
| numpy / scipy / matplotlib / tensorboard | 2.5.4 / 1.18.1 / 3.11.2 / 2.21.0 |
| Скорость обучения | ~0.2 с/итерация при `BATCH_SIZE=2`, `UNROLL=10` |

Фактические версии зафиксированы в `morphogenesis/memory/decisions_log.jsonl`
(§0.3): `numpy==1.26.4` из варианта A под Python 3.13 не собирается, поэтому
`pyproject.toml` описывает диапазоны, а воспроизводимость держится на пинах
`requirements*.txt` и сидах.

### Детерминизм (§9.2) — три правила, которые нельзя нарушать при правках

1. **`import config` обязано идти раньше `import torch`.** Только config умеет
   выставить `CUBLAS_WORKSPACE_CONFIG=":4096:8"` до загрузки CUDA; автоформаттер,
   «оптимизирующий» порядок импортов, молча ломает детерминизм. Проверка —
   `tests/test_determinism.py::test_entry_modules_import_config_first`.
2. **Вся стохастика — через локальный `torch.Generator`.** Один CPU-генератор на
   прогон, значения переносятся на устройство тензора
   (`utils/determinism.rand/randn/randperm`), поэтому энтропийный поток не зависит
   от наличия GPU.
3. **`config.set_seed()` выполняет предзапусковый гейт** `assert_deterministic_ready()`
   (§23): `cudnn.benchmark`, `warn_only`-деградация или поздно выставленная
   переменная окружения — прогон не начнётся.

## Быстрый старт

Все команды выполняются из каталога `morphogenesis/`.

Проверка работоспособности (валидация конфига, прямой/обратный шаг, инварианты стресса и alive-маски):

```bash
python smoke_test.py
```

Обучение:

```bash
python train.py --experiment E02 --seed 42
# возобновить из чекпоинта этой же версии спецификации:
python train.py --resume checkpoints/E02_seed0_stress1/nca_best.pt
# Чекпоинты v5.5 (в т.ч. лежащие локально в checkpoints/E02_seed0_stress1/) не загружаются:
# §13.5 запрещает смешивать веса разных ревизий, check-guard поднимет RuntimeError.
```

Когнитивный контур (название фазы, общее число шагов, интервал отчётов):

```bash
python -m cognition.cognitive_loop "Фаза 7: Нарратив" 500 50
```

## Эксперименты

Полная серия запускается одной командой (поочерёдно выполняет E01–E07):

```bash
python experiment_manager.py
```

| ID | Название | Что проверяет |
| --- | --- | --- |
| **E01** | criticality | Сканирование критичности, показатель Ляпунова в целевом коридоре |
| **E02** | pattern (paired) | Парное обучение паттерну; первичная метрика — `final_mse` |
| **E03** | injury (paired) | Травма и восстановление; первичная метрика — `recovery_steps` |
| **E04** | topology | Достижение целевой топологии (β₀, β₁, χ) |
| **E05** | aging | Старение/омоложение, sweep по уровню шума |
| **E06** | narration | Нарративная фаза когнитивного контура |
| **E07** | control ablation | Контрольная абляция стресс-механизма |

Абляции стресса требуют **минимум 6 сидов** (рекомендуется 10, подтверждающий прогон 15) и парного теста Уилкоксона с effect size и bootstrap CI.

## Конфигурация

Все гиперпараметры собраны в `morphogenesis/config.py` и **не должны** хардкодиться в других файлах. Функция `config.validate()` проверяет абсолютные правила (размер сетки, бюджет вмешательств, зарезервированные каналы, воспроизводимость и т.д.) — она вызывается при старте и в smoke-тесте.

## Зависимости

Файлы `requirements.txt` (ядро) и `requirements-cuda.txt` (CUDA-сборка torch)
задают диапазоны, работающие на Python 3.12 и 3.13; строгие пины лежат в
закомментированном «варианте A» и применимы только к Python 3.12 (под 3.13
`numpy==1.26.4` не собирается). Фактические версии каждого прогона фиксируются в
`morphogenesis/memory/decisions_log.jsonl` (§0.3).

- `torch` (CPU или `+cu124`), `numpy`, `scipy`, `matplotlib`, `tensorboard`, `pytest`
- `llama-cpp-python` — НЕ входит в MVP: локальный LLM-бэкенд относится к слою 5 (кора) и подключается только после прохода гейтов слоёв 0–2 (§1.8, §19.6).
