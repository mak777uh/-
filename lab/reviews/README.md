# Ревью утверждений (lab/reviews/)

Здесь работает роль **reviewer** — научный рецензент-скептик. Его задача: по каждому заявленному
утверждению пересчитать числа из **сырых артефактов** и найти то, что убьёт утверждение при внешней
рецензии. Он не правит рукопись и не меняет статусы — решение принимает ведущий.

## Формат файла

`lab/reviews/<YYYY-MM-DD>-<короткий-id>.md`:

```markdown
# Проверка: <утверждение своими словами, одно предложение>
- **Раздел/строка CLAIMS:** §4i / строка «Клеточное почкование делает линию единицей отбора»
- **Вердикт:** держится | не держится | держится с оговоркой | проверить нельзя
- **Что пересчитано:** файлы, величины, команды
- **Расхождение:** число из текста против пересчёта (если есть)
- **Проверки на устойчивость:** варианты определения и результат
- **Что убьёт утверждение:** конкретный тест, который его опровергнет
- **Что предложить ведущему:** одна-две строки
```

## Индекс

`lab/reviews/index.json` — машинный список:

```json
{"reviews": [{"file": "...", "claim": "...", "section": "4i", "verdict": "holds",
              "date": "2026-10-25", "checked_numbers": ["I_obs_median", "I_ratio_median"]}]}
```

## Гейт

`python scripts/check_reviews.py` (в CI и в `make verify`):

- каждый `.md` имеет вердикт из четырёх допустимых и заполненные «Что пересчитано» и «Что убьёт»;
- `index.json` покрывает все файлы, вердикты совпадают с файлами;
- ревью «держится» обязано ссылаться на артефакт или команду пересчёта — иначе это мнение, а не проверка;
- ревью старше 7 дней по утверждению, которое до сих пор `подтверждено`, помечается как устаревшее.

## Кто проверяет рецензента

**Ведущий, раз в цикл.** Ревью, которое не перепроверено, — это ещё одно непроверенное утверждение.
Правило: раз в 3-часовой цикл ведущий берёт **одно** ревью рецензента и пересчитывает его сам; если
расходится — ревью переводится в `проверить нельзя`, а расхождение записывается в `lab/notices.md`.
