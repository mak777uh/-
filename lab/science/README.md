# lab/science — научные карточки прогонов (слой B)

Один прогон — один файл `<run_id>.json`. Имя файла = `run_id` манифеста в
`lab/runs/`, чтобы связь была однозначной.

Зачем отдельный слой: `lab/runs/<run_id>.json` — манифест раннера (команда,
коммит, окружение, статус), и по контракту (§2, §7 AGENTS.md) он **не
переписывается** задним числом. Научные поля (класс, метрики, пре-регистрация)
появляются позже раннера, поэтому живут отдельным файлом. Дедуп и сводка — в
`lab/runs.index.json`, который генерируется скриптом.

## Схема

`lab/schema/run.schema.json` (JSON Schema 2020-12). Проверка:

```bash
python scripts/validate_runs.py        # из корня репозитория
```

CI запускает то же самое; битый JSON или поле вне enum — красный прогон.

## Правила заполнения

1. **Только из артефактов.** Класс — из `summary_*.json`, метрики — из
   `journal.jsonl` / манифеста / сводки. Нет данных — `null` и запись в `notes`,
   а не оценка «по памяти».
2. **`preregistered`**: `true` — только если в репозитории есть план с критерием,
   закоммиченный до старта прогона; `unknown` — иначе (история в основном такая).
3. **`regime`** — это точность, а не железо: `tf32`, `fp32`, `fp32_no_tf32_hw`
   (карта без TF32, например Turing T4/V100), `cpu`, `unknown`. Железо и версии —
   в `env`.
4. **`class`** — доминирующий класс переписи: `struct_1`, `struct_2`,
   `uniform_dark`, `uniform_bright`, `death`, `mixed` (ни один класс не набрал
   порога), `n/a` (переписи не было), `unknown`.
5. **`source: converted`** ставит скрипт, `manual` — человек. Переконвертировать
   историю можно, ручные карточки скрипт не перезаписывает.

## Кто заполняет

- исполнитель/ведущий — после переписи, когда класс известен;
- исторические прогоны — `scripts/convert_runs.py` (только из артефактов);
- CI проверяет формат, а не научную истинность: за числа отвечает тот, кто
  заполнял, и ссылка на артефакт в самой карточке.
