## M-1 (HIGH) — восемь наборов тестов и ни одного места, где они запускаются

**Что обещает README.** Задокументированная команда:

```
$ grep -n 'pytest' README.md
168: python -m pytest tests/ -p no:libtmux -v
191: - `pytest >= 7.0.0` *(для тестов)*
```

**Что в дереве.**

```
$ ls .github/workflows
ls: cannot access '.github/workflows': No such file or directory
$ ls morphogenesis/tests/test_*.py | wc -l
7
```

**Почему это находка.** Команда есть, исполнителя нет: ни один коммит не прогоняет набор, и «тесты зелёные» — это
утверждение о последнем запуске автора, а не о дереве. Дополнительно: у вас `torch` импортируется в 24 местах
пакета, и без него набор не запустится вообще — то есть проверка требует ещё и среды, которую никто не
фиксирует.

**Что предлагаю.** Один workflow на `push`/`pull_request`: установка зависимостей из вашего же объявленного
минимума, `python -m pytest tests/ -p no:libtmux -q`, падение на ненулевом коде. Если часть наборов требует GPU
или минуты времени — разделить на `fast` (в PR) и `slow` (ночью), как это сделано у `VecDHT`.

## M-2 (MEDIUM) — две версии спецификации в корне, и ни одна не объявлена текущей

```
$ ls -la *.md
спецификация исследования, проверка гипотез Майкла Левина (30).md   211 KB
спецификация исследования, проверка гипотез Майкла Левина (31).md   362 KB
README.md
```

Первая начинается «📜 PROJECT MORPHOGENESIS: ПОЛНАЯ ИНСТРУКЦИЯ … Версия: v5.5-EXP FINAL Ревизия: Rev.7». Вторая —
«Принял. Перевожу проект с `v5.4-EXP FINAL` на **`v5.5-EXP FINAL (Rev.7)** поэтапно… Часть 1: критическое ядро».

**Почему это находка.** Два файла объявляют одну и ту же версию (`v5.5-EXP FINAL Rev.7`), но один из них —
инструкция, а другой — план перехода. Читатель не может узнать, какой из них действующий, а суффиксы `(30)` и
`(31)` не значат ничего без внешнего ключа. Это не придирка к именам: при 211 и 362 КБ расхождение между ними
никто не заметит глазами, а спека — единственный носитель требований.

**Что предлагаю.** Либо один файл с явной шапкой «действующая версия», либо каталог `spec/` с
`CURRENT -> v5.5-rev7.md` и правило «правка только в действующую версию». Форма та же, что у нас в
`docs/10-SPEC`: одна конституция, остальные документы ссылаются на неё.
