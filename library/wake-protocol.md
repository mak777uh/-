# Протокол пробуждения библиотекаря и циклы

Документ для ведущего: как библиотекарь узнаёт, что пора работать, и какие изменения
контракта нужны, чтобы это стало событийным, а не календарным.

Статус: **частично реализовано** (2026-10-23). Ниже — что уже работает, что предлагается
и что для этого нужно поменять.

## 1. Что уже работает

| Механизм | Файл/команда | Когда срабатывает |
| --- | --- | --- |
| Дежурство по календарю | cron 09:00–21:00 каждые 2 часа | гарантия: даже если всё проспано |
| Быстрая проверка изменений | `python scripts/library_wake.py --check` | дешёвый предикат в начале каждого дежурства |
| Ожидание события (supervised) | `python scripts/library_wake.py --wait --timeout 3600` | когда библиотекарь явно «сторожит» окно (эксперимент бежит) |
| Доска замечаний | `lab/lit-board.json` + `lit_board.py` | после решения ведущего появляется `accepted/declined/deferred` |
| Задание | `library_brief.py` | при каждом дежурстве; включает доску |
| Глубокий проход | пн/чт 11:00 | новые источники и конспекты |
| Аудит | 1-е число, 12:00 | пере-сверка метаданных |

`library_wake.py` отслеживает: число строк и хеш последней строки `journal.jsonl`;
файлы и mtime в `reports/`, `articles/`; версию/заголовки `manuscript/paper.md`; открытые
пункты `lit-queue.json`; замечания текущей волны в `lit-board.json`; `lab/cycle.json`;
`HEAD`. Снимок — `_hourly/.lib-wake-state.json` (вне репозитория).

**Почему не фоновый watcher круглосуточно.** Контракт §7 запрещает оставлять фоновый
процесс. Поэтому `--wait` используется только как supervised-инструмент на время, пока
библиотекарь активно ждёт окно; в остальное время работает `--check` на дежурстве. Если
хотите настоящий event-driven — нужен журнал событий (п. 3), а не процесс.

## 1a. Что уже машинно проверяется (2026-10-23)

- **`type` волны:** `research` (гипотезы, прогоны) или `review` (обзор/литература).
  Без `type` `validate` предупреждает; неизвестный тип — ошибка.
- **Выход фазы `prepare`.** При `phase` = `run`/`interpret`/`close` `validate` требует, чтобы
  с `started_at` был коммит в `library/answers.md`, `library/synthesis/*.md` (для
  `review` — ещё `library/review-*.md`). Если выход не нужен — `prepare_output:
  "not_needed: причина"` в цикле. На `run` это предупреждение, дальше — ошибка.
- **Решения по доске.** На `interpret` открытые замечания к гипотезам волны дают
  предупреждение, на `close` — ошибку. Смысл: волна не закрывается с нерешёнными
  замечаниями.
- **Архив волн:** `lab/cycles/*.json` (необязателен); если есть — проверяются id, фаза,
  гипотезы, дубликаты.
- **Лог циклов:** `python scripts/library_cycle_log.py` пересобирает
  [`cycle-log.md`](cycle-log.md) из фаз, git, доски и инсайтов. Одна строка на фазу:
  какие файлы библиотеки затронуты, какие решения доски приняты, какие инсайты появились.
- **Предел инсайтов** поднят с 5 до 12: жёсткий блок защищает от свалки, а не мешает
  зарегистрировать находку в момент чтения (24-часовое правило в `--check` остаётся).

## 2. Что предлагается: цикл как объект (`lab/cycle.json`)

Прототип уже лежит: `lab/cycle.json`.

```json
{
  "schema_version": 1,
  "id": "W-2026-10-23-p1",
  "type": "research",
  "wave": "P1: обучение политики размещения (пруд)",
  "phase": "run",
  "started_at": "2026-10-23T15:35:00+03:00",
  "hypothesis_ids": ["H33", "H34", "H40", "H41"],
  "expected_artifacts": ["reports/2026-10-23-*pond*", "lab/queue.json → task-1"]
}
```

Фазы: `prepare` (библиотекарь готовит ответы/абзацы заранее), `run` (тишина, только
сторож), `interpret` (числа есть, интерпретации нет — лучшее окно для замечаний),
`close` (проверка решений по доске и «доска: принято N…» в отчёте).

Что нужно от ведущего:
1. Владелец цикла (ведущий) обновляет `id/phase` при старте и смене фазы волны.
2. `validate`: `id` непустой, `phase` из набора, `hypothesis_ids` существуют (в реестре
   или в библиотечных H-номерах), `expected_artifacts` не пусты.
3. В `notices.md` одна строка «волна X: phase=…», чтобы библиотекарь не угадывал.

## 3. Что предлагается: журнал событий (`lab/lit-events.jsonl`)

Вместо опроса — объявление событий теми инструментами, которые уже знают факт.

```json
{"id":"E-0001","type":"run_finished","target":"E02c_...","payload":{"class":"struct_2"},
 "created_at":"…","consumed_at":null}
```

Писатели (по одному вызову):
- `lab.py run` — `run_started` / `run_finished` / `run_failed`;
- `item-claim` — `wave_started` / `item_closed`;
- `journal-import` — `journal_imported`;
- git post-commit (или CI-шаг) — `report_added`, `article_added`, `manuscript_changed`
  (только для путей `reports/`, `articles/`, `manuscript/`, `lab/registry.json`).

Читатель: библиотекарь на дежурстве закрывает события (`consumed_at`). `validate`:
событие старше 6 часов без `consumed_at` — предупреждение; неизвестный `type` — ошибка.

Почему это лучше watcher'а: не нужен процесс, события батчатся, история видна людям,
после падения ничего не теряется.

## 4. Что будит, а что нет

| Будит | Не будит |
| --- | --- |
| `run_finished` / новый `summary_*.json` | коммиты только с кодом и тестами |
| новый отчёт, статья, раздел рукописи | правки README, логов, retention |
| новый пункт `lit-queue`, новая гипотеза | пустой скан `lit_check --scan` |
| смена `cycle.phase` (особенно `interpret`) | смена `lab/state.json` |
| решение по замечанию, требующее действия | `deferred`-замечания |
| инсайт без действия > 24 ч | собственные cron-тики без изменений |

Правило шума: ≤ 3 новых замечаний за проверку, ≤ 10 открытых на волну; если за проверку
нет ни одного actionable вывода — одна строка и без коммита.

## 5. Что библиотекарь делает на каждом пробуждении

1. `library_wake.py --check` → что именно изменилось (журнал/отчёты/рукопись/очередь/доска/волна).
2. Если изменился журнал или отчёты: прочитать **только дельту**, найти «это уже известно /
   нужен базлайн / называется иначе / противоречит источнику» → замечание на доску.
3. Если сменилась фаза на `prepare`: заранее положить в `answers.md` ответы под гипотезы
   волны и абзац в `synthesis/`.
4. Если фаза `close`: проверить, что у каждого замечания к цели есть решение; иначе строка
   в `notices.md`.
5. Отчитаться одной строкой: что нового, что подготовлено, где лежит.

## 6. Порядок внедрения (что сделать ведущему)

1. Взять `lab/cycle.json` как владельческий файл: обновлять `phase`, добавить схему в
   `validate`.
2. Если событийный режим нужен — добавить `lab/lit-events.jsonl` и три вызова из п. 3;
   библиотекарь переключится с `--check` на дренаж.
3. Добавить строку в отчёт §6.7a: «события: N, отработано M» рядом с «доска: принято…».
4. До внедрения п. 2 всё работает как сейчас: cron + `--check` + доска.
