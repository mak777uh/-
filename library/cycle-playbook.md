# Плейбук цикла библиотеки

Правило одно: **цикл не осматривается — цикл закрывает один пункт очереди.**

## Пять фаз (общий бюджет 10 минут)

| Фаза | Команда | Выход |
|---|---|---|
| 1. Наблюдение | `python scripts/lib_cycle.py status` | события с прошлого цикла + следующий пункт |
| 2. Задача | (выбор машиной по impact/effort) | `W<n>` с действием и целью |
| 3. Работа | по `action` пункта | один артефакт: файл/строка/расчёт |
| 4. Проверка | `python scripts/claim_audit.py` / `lab.py validate` | 0 проблем |
| 5. Учёт | `python scripts/lib_cycle.py done W<n> --note "…"` | строка в `library/cycle-log.md` |

Без шага 5 цикл не считается выполненным (журнал — единственное доказательство пользы).

## Правила выбора работы

1. Машина берёт пункт с максимальным `impact/effort`, у которого нет незакрытых блокеров.
2. Если пункт требует новых данных — он остаётся, а в `notices` уходит одна строка с просьбой;
   цикл переключается на следующий доступный.
3. Пункт «чисто литература» ставится только если он разблокирует условие A–E.
4. Пункты не дублируются: один факт — одна запись (`notices` — учёному, `answers` — выводы,
   `synthesis` — текст, `cycle-log` — что сделано).

## Что считается пользой цикла

- закрытый пункт с артефактом в репозитории;
- или найденная ошибка (тогда пункт переоткрывается с новым `action`);
- или просьба к учёному, сформулированная так, что её можно выполнить одной серией.

«Изменений нет» — допустимый, но не желательный исход: тогда пункт всё равно закрывается
(например, `W9` — гигиена цикла).

## Ритм

- `*/30 9-23` — рабочий крон (каждый цикл двигает очередь);
- событийный сторож — чтобы не ждать до следующего слота;
- раз в день (один из циклов) — обновить `self-audit` и прислать ведущему 3 строки итога.
